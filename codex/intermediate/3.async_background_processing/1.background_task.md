# Background Task

[Lesson index](../../README.md) · [Previous](../2.database_performance/10.connection_pooling.md) · [Next](2.job.md)

## 1. What is it?

A background task runs outside the immediate request-response work, like leaving a repair ticket instead of waiting at the counter.

## 2. Why do we need it?

Slow exports or email calls keep request connections occupied; a process crash can lose work started only in an untracked thread.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Distinguish in-process scheduling from durable handoff. A thread shares process memory and failure fate; a durable job stores recoverable intent. Queue wait plus execution time determines user-visible completion latency, even when the HTTP response is fast.

Reference: [Primary documentation](https://docs.python.org/3/library/concurrent.futures.html).

### 3b. Boundaries and lifecycle

Request validates and authorizes → records intent → returns an operation reference → a separate execution path performs work → status becomes observable.

## 4. How to apply / implement / use it?

Save as `background_task_demo.py`; run `python3 background_task_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
from concurrent.futures import ThreadPoolExecutor
def export(allowed):
    if not allowed:
        raise PermissionError("export denied")
    return "report.csv"
with ThreadPoolExecutor(max_workers=1) as executor:
    accepted = executor.submit(export, True)
    rejected = executor.submit(export, False)
    assert accepted.result() == "report.csv"
    try:
        rejected.result()
    except PermissionError:
        pass
    else:
        raise AssertionError("failure must remain observable")
```

This is a real in-process background task, not durable delivery. The context manager waits for completion. For important work, persist job intent before reporting acceptance; never pass a live request or database connection into an unrelated worker.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not move work off-thread merely to hide latency. Background execution adds status, capacity, cancellation, authorization snapshots, and recovery responsibilities.
