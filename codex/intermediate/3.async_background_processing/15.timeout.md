# Timeout

[Lesson index](../../README.md) · [Previous](14.exponential_backoff.md) · [Next](16.dead_letter_queue.md)

## 1. What is it?

A timeout stops waiting after a budget expires, like leaving a service desk when your allotted waiting time ends.

## 2. Why do we need it?

Requests can hang while holding threads and connections, and nested calls can each consume the entire original budget.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Use monotonic time for local elapsed budgets; derive per-hop budgets from remaining time. Connect, read, queue, execution, and total timeouts cover different waits. Expiring the caller's wait does not cancel remote work or undo committed effects.

Reference: [Primary documentation](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/).

### 3b. Boundaries and lifecycle

Establish deadline → check remaining time before each wait → time out locally → cancel cooperatively if supported → reconcile uncertain outcomes.

## 4. How to apply / implement / use it?

Save as `timeout_demo.py`; run `python3 timeout_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
now = 10.0
deadline = now + 3.0
def remaining():
    budget = deadline - now
    if budget <= 0:
        raise TimeoutError("deadline exhausted")
    return budget
assert remaining() == 3.0
remote_effect = {"committed": False}
now = 14.0
remote_effect["committed"] = True
try:
    remaining()
except TimeoutError:
    pass
else:
    raise AssertionError("expired work allowed")
assert remote_effect["committed"]
```

The fake clock makes deadline behavior deterministic. Use time.monotonic locally; transmit a documented remaining budget or interoperable deadline rather than a machine-local monotonic timestamp.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not equate timeout with cancellation, transaction rollback, or proof an effect did not occur. Excessively short limits create false failures and retry storms.

## 6. How do I know I understand it?

**Blank-page check:** Draw a caller timing out while a server commits successfully. Explain the recovery path without charging twice.

| Constraint change | Predict the failure and response |
| --- | --- |
| Queue wait consumes most of the budget | Reject before expensive work if too little useful time remains. |
| Clock jumps backward | Monotonic elapsed timing avoids wall-clock adjustments locally. |
