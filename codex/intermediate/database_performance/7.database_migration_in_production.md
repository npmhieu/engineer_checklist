# Database Migration in Production

[Lesson index](../../README.md) · [Previous](6.query_optimization.md) · [Next](8.caching.md)

## 1. What is it?

A production migration changes live schema/data while preserving service and recovery, like renovating an occupied hospital rather than an empty model building.

## 2. Why do we need it?

Existing data, mixed application versions, long locks, and replica lag make successful development DDL insufficient evidence.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

DDL lock/rewrite behavior is engine- and operation-specific. Backfills generate logs and I/O; use resumable bounded batches, verification, and capacity budgets. Expand first, deploy compatible readers/writers, backfill, switch, then contract. An application rollback cannot reconstruct dropped data.

Reference: [Primary documentation](https://www.postgresql.org/docs/current/sql-altertable.html).

### 3b. Boundaries and lifecycle

Rehearse on realistic state → backup/restore proof → controlled expansion → verify/backfill → switch → delayed removal with explicit recovery gates.

## 4. How to apply / implement / use it?

Save as `database_migration_in_production_demo.py`; run `python3 database_migration_in_production_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
import sqlite3
database = sqlite3.connect(":memory:")
database.executescript("CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT); INSERT INTO users VALUES (1,'A'),(2,'B');")
database.execute("ALTER TABLE users ADD COLUMN display_name TEXT")
with database:
    database.execute("UPDATE users SET display_name=name WHERE display_name IS NULL AND id<=?", (1,))
assert database.execute("SELECT COALESCE(display_name,name) FROM users ORDER BY id").fetchall() == [("A",), ("B",)]
with database:
    database.execute("UPDATE users SET display_name=name WHERE display_name IS NULL")
assert database.execute("SELECT COUNT(*) FROM users WHERE display_name IS NULL").fetchone()[0] == 0
assert database.execute("SELECT name FROM users WHERE id=1").fetchone()[0] == "A"
database.close()
```

This demonstrates a resumable expansion/backfill and old-column compatibility, not online PostgreSQL DDL or coordinated dual writes. A real rollout must keep both representations consistent while new writes continue.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not run destructive startup synchronization, unbounded backfills, or a column drop while old replicas still read it. Validate rather than assuming a down script is recovery.
