# Shared Platform / Infrastructure

[Lesson index](../../README.md) · [Previous](8.hybrid_architecture.md) · [Next](../testing/1.end_to_end_test.md)

## 1. What is it?

Shared platform infrastructure supplies reusable technical capabilities across teams, like common electricity and roads rather than one shared business department.

## 2. Why do we need it?

Every team rebuilding secrets, telemetry, deployment, or message access duplicates effort and creates inconsistent operational controls.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

A platform provides versioned APIs, libraries, templates, or services with ownership and service objectives. A library shares code but requires consumer upgrades; a service centralizes runtime failure and capacity. Keep domain-specific rules with domain owners.

Reference: [Primary documentation](https://internaldeveloperplatform.org/what-is-an-internal-developer-platform/).

### 3b. Boundaries and lifecycle

Product team adopts supported interface → platform enforces technical guardrails → versioned rollout and escape hatches manage change → platform incidents have explicit owners.

## 4. How to apply / implement / use it?

Save as `shared_platform_infrastructure_demo.py`; run `python3 shared_platform_infrastructure_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
class PlatformLog:
    def __init__(self):
        self.records = []
    def emit(self, service, event, fields):
        allowed = {"request_id", "outcome"}
        if not set(fields) <= allowed:
            raise ValueError("unsupported or sensitive field")
        self.records.append({"service": service, "event": event, **fields})
platform = PlatformLog()
platform.emit("orders", "completed", {"request_id": "req-1", "outcome": "ok"})
assert platform.records[0]["service"] == "orders"
try:
    platform.emit("orders", "completed", {"password": "secret"})
except ValueError:
    pass
else:
    raise AssertionError("unsafe field accepted")
```

This small shared logging contract illustrates technical guardrails, not a production telemetry platform or complete redaction. It must not become the owner of order, billing, or shipping rules.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not centralize everything or force one global release for every shared library change. Shared runtime dependencies increase blast radius; platform teams need supported contracts, feedback, and measured adoption benefits.

## 6. How do I know I understand it?

**Blank-page check:** Choose whether a capability should be a library, template, or service. Explain upgrade ownership and outage impact for each.

| Constraint change | Predict the failure and response |
| --- | --- |
| Shared library changes incompatibly | Version it and migrate consumers deliberately; one repository does not remove compatibility costs. |
| Central telemetry service is down | Bound buffers and degrade safely rather than blocking all customer requests. |
