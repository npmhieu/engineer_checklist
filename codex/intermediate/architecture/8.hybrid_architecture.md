# Hybrid Architecture

[Lesson index](../../README.md) · [Previous](7.infrastructure_layer.md) · [Next](9.shared_platform_infrastructure.md)

## 1. What is it?

Hybrid architecture deliberately combines deployment or interaction styles, like a main workshop using a specialist external lab for one demanding job.

## 2. Why do we need it?

One uniform architecture can force every component to scale, deploy, or coordinate in the same unsuitable way.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Define exactly what is hybrid: monolith plus services, sync plus async, or cloud plus on-premises. Every boundary needs ownership, contracts, failure policy, observability, and data-consistency rules. Avoid writing the same fact authoritatively in two places.

Reference: [Primary documentation](https://learn.microsoft.com/en-us/azure/architecture/patterns/strangler-fig).

### 3b. Boundaries and lifecycle

Route each capability to one owner → adapt at its boundary → reconcile asynchronous replicas → evolve routing only after compatibility and failure tests.

## 4. How to apply / implement / use it?

Save as `hybrid_architecture_demo.py`; run `python3 hybrid_architecture_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
def local_quote(quantity):
    if quantity <= 0:
        raise ValueError("invalid quantity")
    return quantity * 100
def quote(kind, quantity, remote):
    if kind == "standard":
        return local_quote(quantity)
    if kind == "special":
        return remote(quantity)
    raise ValueError("unknown product kind")
assert quote("standard", 2, None) == 200
assert quote("special", 2, lambda quantity: quantity * 150) == 300
def unavailable(quantity):
    raise TimeoutError("specialist unavailable")
try:
    quote("special", 2, unavailable)
except TimeoutError:
    pass
else:
    raise AssertionError("remote failure hidden")
```

The injected specialist models a remote boundary without making network calls. The unhappy path intentionally fails rather than inventing an unauthorized fallback price. Production requires authenticated transport, deadlines, compatible contracts, and explicitly approved degraded behavior.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not use hybrid as a label for accidental inconsistency. Each extra style increases deployment, debugging, staffing, and incident-response complexity.

## 6. How do I know I understand it?

**Blank-page check:** Draw which owner handles each capability and name the failure/consistency policy at every crossing.

| Constraint change | Predict the failure and response |
| --- | --- |
| Specialist service is unavailable | Fail or use a domain-approved stale/degraded result; do not silently change business rules. |
| Traffic moves to a new owner | Avoid dual authoritative writes and validate rollback compatibility. |
