# Bounded Context

[Lesson index](../../README.md) · [Previous](3.ddd_basics.md) · [Next](5.domain_service.md)

## 1. What is it?

A bounded context defines where one domain model and vocabulary have a precise meaning, like the word account meaning different things in banking and sales.

## 2. Why do we need it?

A shared universal Customer or Status object accumulates contradictory fields and couples teams with different rules.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Each context owns language, model, and rules. A context map describes collaboration; translation at boundaries prevents foreign assumptions contaminating the local model. Contexts need not be separate processes, databases, teams, or microservices.

Reference: [Primary documentation](https://martinfowler.com/bliki/BoundedContext.html).

### 3b. Boundaries and lifecycle

Receive external contract → validate and translate → apply local model → publish a context-owned contract; preserve ownership instead of sharing internal entities.

## 4. How to apply / implement / use it?

Save as `bounded_context_demo.py`; run `python3 bounded_context_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
from dataclasses import dataclass
@dataclass(frozen=True)
class ShippingDestination:
    recipient: str
    address: str
def translate_sales(customer):
    if customer.get("delivery_address") is None:
        raise ValueError("shipping address required")
    return ShippingDestination(customer["name"], customer["delivery_address"])
sales_customer = {"name": "Mai", "credit_limit": 50000,
                  "delivery_address": "Warehouse 4"}
destination = translate_sales(sales_customer)
assert destination == ShippingDestination("Mai", "Warehouse 4")
assert not hasattr(destination, "credit_limit")
try:
    translate_sales({"name": "An"})
except ValueError:
    pass
else:
    raise AssertionError("invalid boundary translation")
```

This real mapping demonstrates two meanings without a network boundary. It does not supply address validation, privacy controls, contract negotiation, or a complete context map.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not create a bounded context for every noun or equate it automatically with one service. Translation adds work, but eliminating it through a universal shared model can cost more coupling.

## 6. How do I know I understand it?

| Constraint change | Predict the failure and response |
| --- | --- |
| Sales renames a field | Update the translation/contract boundary, not shipping's internal vocabulary everywhere. |
| Both contexts run in one process | Semantic ownership still matters; deployment unity does not merge models. |
