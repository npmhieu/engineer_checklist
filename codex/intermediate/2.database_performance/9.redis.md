# Redis

[Lesson index](../../README.md) · [Previous](8.caching.md) · [Next](10.connection_pooling.md)

## 1. What is it?

Redis is a networked data-structure server often used for fast shared state, like a shared indexed workbench rather than one application's private dictionary.

## 2. Why do we need it?

Replicas may need common cache, counters, sets, or streams. An ordinary local dictionary does not provide shared atomic commands, expiry, or server persistence behavior.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Strings, hashes, lists, sets, sorted sets, and streams have distinct costs. Single commands are atomic in their execution context; several commands do not automatically form one atomic workflow. MULTI/EXEC is not SQL rollback after command errors. TTL, eviction, replication, and RDB/AOF settings determine loss/freshness behavior; Redis is not inherently durable merely because it is remote.

Reference: [Primary documentation](https://redis.io/docs/latest/develop/data-types/).

### 3b. Boundaries and lifecycle

Choose a data model → authenticated private connection → bounded command(s)/atomic script → handle expiry, eviction, reconnect, and failure under the application contract.

## 4. How to apply / implement / use it?

Save as `redis_demo.py`; run `python3 redis_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
clock = [0]
entries = {}
def set_nx_px(key, value, milliseconds):
    previous = entries.get(key)
    if previous and previous[1] > clock[0]:
        return False
    entries[key] = (value, clock[0] + milliseconds)
    return True
assert set_nx_px("lease", "owner-A", 1000)
assert not set_nx_px("lease", "owner-B", 1000)
clock[0] = 1001
assert set_nx_px("lease", "owner-B", 1000)
if entries["lease"][0] == "owner-A":
    del entries["lease"]
assert entries["lease"][0] == "owner-B"
```

This is an explicitly offline semantic model, not Redis or a distributed lock proof. With a private local Redis, redis-cli SET lesson:key value NX PX 1000 returns OK once, then nil until expiry; redis-cli GET lesson:key reads it. Ownership-safe release requires an atomic comparison/delete script. Lease expiry does not stop an old worker; downstream fencing may be required.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not expose unauthenticated Redis publicly, use KEYS on a large production keyspace, or treat an expiring lock as exactly-once execution. Bound memory/cardinality and choose persistence/security deliberately.
