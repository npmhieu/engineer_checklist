# Dead Letter Queue (DLQ)

[Lesson index](../../README.md) · [Previous](15.timeout.md) · [Next](17.duplicate_processing.md)

## 1. What is it?

A dead letter queue isolates deliveries that cannot currently be processed, like a clearly labeled investigation tray for problematic tickets.

## 2. Why do we need it?

Poison messages can loop forever, block useful work, and disappear into logs with no recovery path.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Preserve protected payload/reference, original identity, reason, attempt metadata, and retention policy. Broker dead-letter routing has product-specific guarantees and can itself fail; do not assume a DLQ is infallible storage.

Reference: [Primary documentation](https://www.rabbitmq.com/docs/dlx).

### 3b. Boundaries and lifecycle

Validate or exhaust retries → quarantine durably → alert an owner → inspect/fix cause → redrive at a controlled rate with the original deduplication identity.

## 4. How to apply / implement / use it?

Save as `dead_letter_queue_demo.py`; run `python3 dead_letter_queue_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
from collections import deque
pending = deque([{"id": "good", "amount": 5}, {"id": "bad", "amount": -2}])
dead, completed = [], []
while pending:
    message = pending.popleft()
    if message["amount"] <= 0:
        dead.append({"message": message, "reason": "invalid amount"})
    else:
        completed.append(message["id"])
assert completed == ["good"]
assert dead[0]["message"]["id"] == "bad"
assert dead[0]["reason"] == "invalid amount"
assert not pending
```

This is a local quarantine model, not configured RabbitMQ dead-lettering. Production needs atomic/safe transfer semantics appropriate to the broker, access controls, retention, alarms, and audited redrive tooling.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not treat the DLQ as a trash can or automatically replay it forever. It can contain sensitive data and old messages that are no longer valid to execute.
