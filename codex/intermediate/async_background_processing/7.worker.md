# Worker

[Lesson index](../../README.md) · [Previous](6.consumer.md) · [Next](8.cronjob.md)

## 1. What is it?

A worker is an execution process that runs jobs or message handlers, like the staffed workshop rather than the ticket itself.

## 2. Why do we need it?

Unbounded executors, abrupt shutdown, and shared request resources cause memory exhaustion, lost progress, and contention.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Workers own execution slots, dependency connections, lifecycle hooks, and shutdown policy. Concurrency is limited by the scarcest resource, not CPU count alone. Stop intake before draining active work, then release connections.

Reference: [Primary documentation](https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/).

### 3b. Boundaries and lifecycle

Start → initialize → acquire work → execute within limits → record outcome → stop intake → finish or safely relinquish work → exit.

## 4. How to apply / implement / use it?

Save as `worker_demo.py`; run `python3 worker_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
from collections import deque
pending = deque(["first", "second"])
completed = []
stopping = False
def tick():
    if stopping or not pending:
        return False
    completed.append(pending.popleft())
    return True
assert tick()
stopping = True
assert not tick()
assert completed == ["first"] and list(pending) == ["second"]
```

This deterministic lifecycle model does not spawn a separate process or handle OS signals. Real shutdown must coordinate signals, visibility leases, acknowledgement, in-flight deadlines, and orchestration grace periods.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not start a heavyweight worker for a tiny local computation or scale workers beyond database pools/provider quotas. More workers can reduce throughput through contention.

## 6. How do I know I understand it?

**Blank-page check:** Draw worker startup and graceful termination. Distinguish process identity, job identity, attempt identity, and leased ownership.

| Constraint change | Predict the failure and response |
| --- | --- |
| Termination grace is shorter than work | Checkpoint or release for retry; do not assume finishing is guaranteed. |
| Worker count doubles | Recalculate connections, prefetch, memory, and provider request rate. |
