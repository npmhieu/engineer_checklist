# Job

[Lesson index](../../README.md) · [Previous](1.background_task.md) · [Next](3.message.md)

## 1. What is it?

A job is a tracked unit of intended work with identity and state, like a numbered repair order.

## 2. Why do we need it?

Without a durable work record, users cannot distinguish queued, failed, retried, or already completed operations.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Separate stable job identity from execution-attempt identity. Persist state transitions with conditional updates and timestamps. Large payloads belong in protected object storage referenced by the job, not duplicated in every attempt.

Reference: [Primary documentation](https://docs.aws.amazon.com/batch/latest/userguide/job_states.html).

### 3b. Boundaries and lifecycle

Create job → claim eligible work → run attempt → store result or failure → allow authorized status lookup; retries keep the same logical job.

## 4. How to apply / implement / use it?

Save as `job_demo.py`; run `python3 job_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
jobs = {}
def create(job_id, tenant):
    if job_id in jobs:
        raise ValueError("job already exists")
    jobs[job_id] = {"tenant": tenant, "state": "queued"}
def status(job_id, tenant):
    job = jobs[job_id]
    if job["tenant"] != tenant:
        raise PermissionError("wrong tenant")
    return job["state"]
create("export-1", "shop-1")
assert status("export-1", "shop-1") == "queued"
try:
    status("export-1", "shop-2")
except PermissionError:
    pass
else:
    raise AssertionError("cross-tenant status exposed")
```

The dictionary models identity and authorization only. Production needs durable records, atomic claims, bounded result retention, and a separate authenticated endpoint.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not make every tiny synchronous calculation a job. Tracking and storage can cost more than the work; do not treat job IDs as authorization secrets.
