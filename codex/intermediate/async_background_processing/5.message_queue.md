# Message Queue

[Lesson index](../../README.md) · [Previous](4.producer.md) · [Next](6.consumer.md)

## 1. What is it?

A message queue buffers deliveries between senders and competing receivers, like a ticket line feeding available clerks.

## 2. Why do we need it?

Without buffering, a traffic burst overwhelms a slow dependency or forces callers to wait for every downstream operation.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Capacity, persistence, replication, prefetch, acknowledgement, and redelivery are separate settings. Memory/disk use grows with retained bytes. Queue depth alone hides long-running work; observe oldest-message age and processing throughput too.

Reference: [Primary documentation](https://docs.python.org/3/library/queue.html).

### 3b. Boundaries and lifecycle

Publish → ready → delivered/in flight → acknowledged, redelivered, or quarantined. Broker acceptance and business completion are different milestones.

## 4. How to apply / implement / use it?

Save as `message_queue_demo.py`; run `python3 message_queue_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
from queue import Queue, Full, Empty
queue = Queue(maxsize=1)
queue.put_nowait("job-1")
try:
    queue.put_nowait("job-2")
except Full:
    pass
else:
    raise AssertionError("unbounded admission")
assert queue.get_nowait() == "job-1"
queue.task_done()
queue.join()
try:
    queue.get_nowait()
except Empty:
    pass
else:
    raise AssertionError("empty queue returned work")
```

Python Queue demonstrates bounded local buffering, not broker durability, automatic redelivery, or replicated acknowledgement. task_done is local bookkeeping, not a remote broker acknowledgement.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not use a queue when immediate transactional confirmation is required without an asynchronous product design. Infinite queues turn overload into disk exhaustion and extreme latency.
