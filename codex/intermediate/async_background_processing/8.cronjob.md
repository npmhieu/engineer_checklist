# Cronjob

[Lesson index](../../README.md) · [Previous](7.worker.md) · [Next](9.event.md)

## 1. What is it?

A cronjob schedules work for calendar times, like an alarm that reminds a worker to create a daily report.

## 2. Why do we need it?

Humans forget routine maintenance; naive per-instance timers also duplicate scheduled work when replicas multiply.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

A scheduler evaluates wall-clock schedules and launches attempts. Time zones, daylight-saving changes, missed schedules, concurrency policy, and catch-up behavior affect execution. Use a stable business-period key; the scheduler is not an exactly-once business guarantee.

Reference: [Primary documentation](https://kubernetes.io/docs/concepts/workloads/controllers/cron-jobs/).

### 3b. Boundaries and lifecycle

Scheduled instant → create job for logical period → claim or deduplicate period → execute → record outcome; monitor missed and late periods.

## 4. How to apply / implement / use it?

Save as `cronjob_demo.py`; run `python3 cronjob_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
import sqlite3
database = sqlite3.connect(":memory:")
database.execute("CREATE TABLE reports(period TEXT PRIMARY KEY)")
def run(period):
    with database:
        changed = database.execute(
            "INSERT OR IGNORE INTO reports VALUES (?)", (period,)).rowcount
    return bool(changed)
assert run("2026-10-17:UTC")
assert not run("2026-10-17:UTC")
assert run("2026-10-18:UTC")
database.close()
```

The SQLite record models transactional per-period local work, not a scheduler. Production must atomically include report metadata or outbox intent; an external effect after this insert would create a loss window.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not use calendar scheduling for immediate event reactions. Avoid node-local cron for shared business work unless duplication and missed-node behavior are deliberate.

## 6. How do I know I understand it?

**Blank-page check:** Explain schedule time versus execution time versus business reporting period. Predict a duplicate trigger and a missed trigger.

| Constraint change | Predict the failure and response |
| --- | --- |
| Two schedulers trigger the same period | A durable unique period key prevents repeated local completion. |
| Daylight-saving time changes | Define time zone and catch-up semantics rather than assuming every day has 24 hours. |
