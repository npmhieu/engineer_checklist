# Correlation ID

[Lesson index](../../README.md) · [Previous](6.request_id.md) · [Next](8.distributed_tracing.md)

## 1. What is it?

A correlation ID links related operations across a workflow, like one case number covering several phone calls and letters.

## 2. Why do we need it?

A long-running export or checkout may span many requests, jobs, and retries that cannot be followed with one request-attempt ID.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Choose a documented workflow scope and propagate bounded metadata across approved boundaries. Keep correlation ID distinct from event ID, job ID, idempotency key, and authenticated tenant context. It may outlive any individual trace.

Reference: [Primary documentation](https://opentelemetry.io/docs/concepts/context-propagation/).

### 3b. Boundaries and lifecycle

Start workflow → record correlation → propagate into job/message metadata → include in downstream evidence → authorize searches and status independently.

## 4. How to apply / implement / use it?

Save as `correlation_id_demo.py`; run `python3 correlation_id_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
from uuid import uuid4
workflow = uuid4().hex
def envelope(correlation, event_id):
    if len(correlation) != 32 or any(char not in "0123456789abcdef" for char in correlation):
        raise ValueError("invalid correlation")
    return {"correlation_id": correlation, "event_id": event_id}
first = envelope(workflow, "event-1")
second = envelope(workflow, "event-2")
assert first["correlation_id"] == second["correlation_id"]
assert first["event_id"] != second["event_id"]
try:
    envelope("bad\nvalue", "event-3")
except ValueError:
    pass
else:
    raise AssertionError("invalid metadata accepted")
```

This fixture adopts one local UUID-hex correlation convention; no universal correlation-ID format is implied. The model does not authenticate messages or grant access to other tenants' logs and jobs.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not reuse one correlation ID forever for all activity by a customer or treat it as deduplication identity. Excessively broad scope makes investigation noisy and increases privacy linkage.
