# Structured Logging

[Lesson index](../../README.md) · [Previous](../testing/6.basic_performance_test.md) · [Next](2.metrics.md)

## 1. What is it?

Structured logging emits named fields in a consistent format, like filling labeled form boxes instead of writing an unsearchable diary sentence.

## 2. Why do we need it?

Free-text logs are hard to query reliably, and unescaped user text can forge apparent entries or expose credentials.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Use stable event names, timestamp, severity, service, outcome, and bounded context. JSON encoding preserves field boundaries; collectors parse/index fields at storage and CPU cost. Structure alone does not redact secrets, guarantee delivery, or make high-cardinality indexing cheap.

Reference: [Primary documentation](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html).

### 3b. Boundaries and lifecycle

Application emits sanitized event → bounded buffer/collector → protected storage → indexed query and retention policy; correlation fields link evidence across requests.

## 4. How to apply / implement / use it?

Save as `structured_logging_demo.py`; run `python3 structured_logging_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
import json
def log(event, fields):
    allowed = {"request_id", "outcome"}
    if not set(fields) <= allowed:
        raise ValueError("unexpected log field")
    return json.dumps({"event": event, **fields}, separators=(",", ":"))
line = log("task.completed", {"request_id": "req-1", "outcome": "ok\nforged"})
assert len(line.splitlines()) == 1
assert json.loads(line)["outcome"] == "ok\nforged"
try:
    log("login.failed", {"password": "secret"})
except ValueError:
    pass
else:
    raise AssertionError("secret field accepted")
```

This real JSON example protects record framing and rejects unapproved field names. It does not validate approved field values, add timestamps, ship logs, or ensure complete redaction. Use trusted event names and bounded, validated context values.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not log raw bodies, tokens, or arbitrary object dumps. Logging every loop iteration can dominate I/O; synchronous remote logging can turn telemetry failure into an application outage.
