# CI/CD Pipeline

[Lesson index](../../README.md) · [Previous](1.docker_containers.md) · [Next](3.production_deployment.md)

## 1. What is it?

A CI/CD pipeline is an automated sequence that verifies, packages, and promotes a change, like an assembly line with quality gates and a traceable finished product.

## 2. Why do we need it?

Manual releases skip checks, rebuild different bytes for each environment, and make it unclear which reviewed source produced a running artifact.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

CI checks source changes; delivery prepares a releasable artifact; deployment promotes it under policy. A dependency graph of jobs gates promotion. Record source, artifact digest, configuration, and approvals; separate untrusted test execution from privileged deployment credentials.

Reference: [Primary documentation](https://docs.github.com/en/actions/reference/security/secure-use).

### 3b. Boundaries and lifecycle

Checkout reviewed revision → run required checks → build once → identify artifact → verify in staging → approve/promote the same artifact → observe and recover.

## 4. How to apply / implement / use it?

Save as `ci_cd_pipeline_demo.py`; run `python3 ci_cd_pipeline_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
from pathlib import Path
import hashlib
import subprocess
import sys
import tempfile
def pipeline(directory, passes):
    subprocess.run([sys.executable, "-c",
                    "raise SystemExit(0)" if passes else "raise SystemExit(1)"],
                   check=True, capture_output=True, timeout=5)
    artifact = Path(directory) / "artifact.txt"
    artifact.write_bytes(b"reviewed-source:lesson-v1\n")
    return hashlib.sha256(artifact.read_bytes()).hexdigest()
with tempfile.TemporaryDirectory() as good:
    digest = pipeline(good, True)
    assert len(digest) == 64
    assert (Path(good) / "artifact.txt").exists()
with tempfile.TemporaryDirectory() as bad:
    try:
        pipeline(bad, False)
    except subprocess.CalledProcessError:
        pass
    else:
        raise AssertionError("failed checks allowed promotion")
    assert not (Path(bad) / "artifact.txt").exists()
```

This real local subprocess/file gate models pipeline dependencies and artifact identity; the subprocess is a controlled stand-in for the project's actual test command. It is not a configured hosted CI runner, signed build, registry push, or deployment. A digest identifies bytes, not their trustworthiness.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not deploy untrusted pull-request code with production secrets, use excessive runner permissions, or rebuild untracked artifacts during promotion. Pin third-party actions/dependencies according to reviewed policy.

## 6. How do I know I understand it?

**Blank-page check:** Draw jobs and permissions, showing which failed gate blocks release and which exact digest reaches each environment.

| Constraint change | Predict the failure and response |
| --- | --- |
| Tests fail but deployment uses an always-run condition | A required dependency gate is bypassed; separate cleanup from promotion. |
| Production rebuilds from the same source tag | Dependency or base-image changes can produce different bytes; promote the tested artifact. |
