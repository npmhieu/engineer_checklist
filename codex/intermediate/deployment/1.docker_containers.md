# Docker / Containers

[Lesson index](../../README.md) · [Previous](../observability/8.distributed_tracing.md) · [Next](2.ci_cd_pipeline.md)

## 1. What is it?

A container runs an application from a packaged filesystem with process/resource isolation, like a prepared workspace using shared building utilities rather than a whole separate building.

## 2. Why do we need it?

Applications fail across machines when runtime dependencies, startup commands, filesystem assumptions, and configuration differ.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Images contain content-addressed filesystem layers and metadata; containers add a writable layer. Linux namespaces isolate views and cgroups constrain resources, while containers share a kernel. Docker Desktop commonly supplies that Linux kernel through a VM. Build caches, image pulls, copy-on-write, and logs incur disk/network work.

Reference: [Primary documentation](https://docs.docker.com/build/concepts/dockerfile/).

### 3b. Boundaries and lifecycle

Build a minimal image → publish immutable identity → run with external configuration and least privilege → observe readiness and signals → replace containers while durable data remains outside their writable layer.

## 4. How to apply / implement / use it?

Save as `docker_containers_demo.py`; run `python3 docker_containers_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
import os
def validate_mode(mode):
    if mode not in {"demo", "production"}:
        raise ValueError("APP_MODE must be demo or production")
    return mode
assert validate_mode("demo") == "demo"
try:
    validate_mode("broken")
except ValueError:
    pass
else:
    raise AssertionError("invalid configuration accepted")
try:
    mode = validate_mode(os.environ.get("APP_MODE", "demo"))
except ValueError as error:
    raise SystemExit(str(error))
print("started in " + mode)
```

The Python run verifies startup configuration only, not container isolation. The optional Docker walkthrough below requires an installed, running Docker Engine and network access to pull the base image; it is not executed by the offline example checks. The invalid container run exits nonzero (Python SystemExit with a string normally exits 1).

### Optional real Docker walkthrough

In a new disposable directory, save the Python block as `docker_containers_demo.py` and create this `Dockerfile`:

```dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY docker_containers_demo.py app.py
USER 10001:10001
ENTRYPOINT ["python", "-B", "app.py"]
```

Build only from this small directory, with no credentials or unrelated files. A minimal `.dockerignore` is:

```text
*
!Dockerfile
!docker_containers_demo.py
```

```sh
docker build -t backend-lesson .
docker run --rm --network none --read-only --cap-drop ALL --security-opt no-new-privileges:true --memory 64m --cpus 1 -e APP_MODE=demo backend-lesson
docker run --rm --network none --read-only --cap-drop ALL --security-opt no-new-privileges:true --memory 64m --cpus 1 -e APP_MODE=broken backend-lesson
```

Expected: first run prints `started in demo` and exits 0; second prints the validation error and exits nonzero. This short-lived demo intentionally has no port or health endpoint. Tags are mutable; production should record a reviewed image digest and regularly rebuild for security fixes. These commands do not deploy a production service.

Security reference: [Docker Engine security](https://docs.docker.com/engine/security/).

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not treat a container as a VM-grade security boundary or durable database backup. Never bake secrets into layers or mount the Docker socket into untrusted workloads. Image scanning, dependency updates, non-root execution, capabilities, and resource limits remain necessary.

| Constraint change | Predict the failure and response |
| --- | --- |
| Container is replaced | Its writable-layer data is not a durable application storage contract; use appropriate external storage. |
| Application runs as root with broad mounts | Isolation can be undermined; apply least privilege and review the host attack surface. |
