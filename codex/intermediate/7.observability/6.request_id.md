# Request ID

[Lesson index](../../README.md) · [Previous](5.alerting.md) · [Next](7.correlation_id.md)

## 1. What is it?

A request ID labels one request attempt for troubleshooting, like a receipt number for one visit to a service desk.

## 2. Why do we need it?

Concurrent logs otherwise cannot be connected reliably to a particular response or support report.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Create or validate a bounded identifier at the entry boundary, attach it to request-local context and response headers, and include it in logs. Clear context after completion. A caller-supplied ID is untrusted metadata, not identity, authorization, or a guaranteed unique value.

Reference: [Primary documentation](https://docs.python.org/3/library/contextvars.html).

### 3b. Boundaries and lifecycle

Receive → establish request ID → propagate within handling → include safe response/log context → reset local context; client retries normally get new attempt IDs.

## 4. How to apply / implement / use it?

Save as `request_id_demo.py`; run `python3 request_id_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
from contextvars import ContextVar
from uuid import uuid4
import re
current = ContextVar("request_id", default=None)
def handle(incoming):
    request_id = incoming if re.fullmatch(r"[A-Za-z0-9_-]{1,64}", incoming or "") else uuid4().hex
    token = current.set(request_id)
    try:
        assert current.get() == request_id
        return {"X-Request-ID": request_id}
    finally:
        current.reset(token)
assert handle("req-123")["X-Request-ID"] == "req-123"
generated = handle("bad\ninjected")["X-Request-ID"]
assert re.fullmatch(r"[0-9a-f]{32}", generated)
assert current.get() is None
```

This uses real context-local storage and bounded syntax. An Internet-facing gateway may choose to replace even syntactically valid incoming IDs to avoid collisions/spoofing; the example accepts them only to show the policy choice. Thread/process propagation is not automatic across all execution boundaries.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not use a request ID as a secret, idempotency key, or metric label. Do not put arbitrary unvalidated headers into logs.

## 6. How do I know I understand it?

**Blank-page check:** Trace a request through entry, logs, response, and cleanup. Explain why two client retries are two attempts but may belong to one operation.

| Constraint change | Predict the failure and response |
| --- | --- |
| Client supplies someone else's ID | Authorization must be unaffected; IDs are evidence hints, not proof of identity. |
| Work moves to another thread/process | Pass or explicitly propagate approved context; do not rely on global variables. |
