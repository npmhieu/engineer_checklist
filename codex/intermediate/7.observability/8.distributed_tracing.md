# Distributed Tracing

[Lesson index](../../README.md) · [Previous](7.correlation_id.md) · [Next](../8.deployment/1.docker_containers.md)

## 1. What is it?

Distributed tracing records related timed spans across components, like a journey map showing each handoff and waiting stage.

## 2. Why do we need it?

A slow response spread across gateway, API, database, and worker cannot be explained by disconnected local duration logs.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Trace identity joins spans; each span has its own identity, timing, attributes, and parent or links. Propagators carry context across transport boundaries. Sampling and export buffering control cost and can omit evidence; overlapping spans must not be summed as if sequential.

Reference: [Primary documentation](https://www.w3.org/TR/trace-context/).

### 3b. Boundaries and lifecycle

Extract or start context → create server span → create child client/database spans → inject downstream → finish/export → inspect the causal graph and critical path.

## 4. How to apply / implement / use it?

Save as `distributed_tracing_demo.py`; run `python3 distributed_tracing_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
import re
import secrets
def parse_parent(header):
    match = re.fullmatch(r"00-([0-9a-f]{32})-([0-9a-f]{16})-([0-9a-f]{2})", header)
    if not match:
        raise ValueError("invalid version-00 traceparent")
    trace_id, parent_id, flags = match.groups()
    if int(trace_id, 16) == 0 or int(parent_id, 16) == 0:
        raise ValueError("zero identity")
    return trace_id, parent_id, flags
incoming = "00-" + "1" * 32 + "-" + "2" * 16 + "-01"
trace_id, parent_id, flags = parse_parent(incoming)
span_id = secrets.token_hex(8)
while int(span_id, 16) == 0 or span_id == parent_id:
    span_id = secrets.token_hex(8)
outgoing = f"00-{trace_id}-{span_id}-{flags}"
assert parse_parent(outgoing) == (trace_id, span_id, flags)
assert span_id != parent_id
try:
    parse_parent("00-" + "0" * 32 + "-" + "2" * 16 + "-01")
except ValueError:
    pass
else:
    raise AssertionError("zero trace accepted")
```

This is a version-00 traceparent identity/propagation model, not an OpenTelemetry SDK or full future-version/tracestate parser. It preserves flags but performs no sampling/export. Production should use maintained propagators, bound untrusted baggage, and avoid sensitive span attributes.

Additional reference: [OpenTelemetry trace concepts](https://opentelemetry.io/docs/concepts/signals/traces/).

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not build a tracing backend or full parser from this example. Tracing is not an audit guarantee; sampling, broken propagation, clock differences, and missing instrumentation limit conclusions.
