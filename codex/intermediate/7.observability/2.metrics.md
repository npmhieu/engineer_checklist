# Metrics

[Lesson index](../../README.md) · [Previous](1.structured_logging.md) · [Next](3.error_tracking.md)

## 1. What is it?

Metrics are numeric measurements summarized over time and bounded dimensions, like dashboard gauges rather than individual incident stories.

## 2. Why do we need it?

Logs alone make it difficult to quantify error rate, latency distribution, saturation, and changes across a fleet.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Counters accumulate events and can reset; gauges vary up/down; histograms summarize distributions. Each label combination creates stored series, so user IDs or raw URLs can explode cardinality. Percentiles from different instances cannot generally be averaged into a correct fleet percentile.

Reference: [Primary documentation](https://prometheus.io/docs/concepts/metric_types/).

### 3b. Boundaries and lifecycle

Observe an operation → update instruments → scrape/export → aggregate over a defined window → dashboard or evaluate objectives.

## 4. How to apply / implement / use it?

Save as `metrics_demo.py`; run `python3 metrics_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
from collections import Counter
counts = Counter()
bounds = [0.1, 0.5, float("inf")]
buckets = {bound: 0 for bound in bounds}
def observe(route, outcome, seconds):
    if route != "/tasks/{id}" or outcome not in {"ok", "error"} or seconds < 0:
        raise ValueError("invalid or unbounded dimensions")
    counts[(route, outcome)] += 1
    for bound in bounds:
        if seconds <= bound:
            buckets[bound] += 1
observe("/tasks/{id}", "ok", 0.05)
observe("/tasks/{id}", "error", 0.7)
assert buckets[0.1] == 1 and buckets[float("inf")] == 2
assert sum(counts.values()) == 2
try:
    observe("/tasks/user-93847", "ok", 0.1)
except ValueError:
    pass
else:
    raise AssertionError("unbounded route accepted")
```

This models a bounded counter and cumulative classic histogram buckets, not a Prometheus client/exporter. Production should use maintained instrumentation, appropriate bucket boundaries, process-safe aggregation, and documented units.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not put request IDs, email addresses, full exception messages, or raw paths in metric labels. Metrics are not an audit trail or a replacement for detailed error evidence.

## 6. How do I know I understand it?

**Blank-page check:** Choose counter, gauge, or histogram for requests, active workers, and latency. Estimate series count from label dimensions.

| Constraint change | Predict the failure and response |
| --- | --- |
| 100 tenants × 20 routes × 5 outcomes × 10 buckets | Thousands of series arise before replicas and other labels; budget cardinality. |
| Process restarts | Handle counter resets with the monitoring system's rate functions. |
