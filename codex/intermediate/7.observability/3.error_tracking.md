# Error Tracking

[Lesson index](../../README.md) · [Previous](2.metrics.md) · [Next](4.monitoring.md)

## 1. What is it?

Error tracking groups failure reports with diagnostic context, like one incident folder collecting repeated sightings of the same defect.

## 2. Why do we need it?

Raw stack traces spread across machines obscure frequency, affected releases, ownership, and whether a supposedly fixed bug returned.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Capture exception type, sanitized stack, release, environment, and scoped correlation context. Fingerprints group related failures; overly broad grouping hides distinct bugs, while raw IDs in fingerprints fragment one bug into thousands of groups. Sampling and rate limits bound ingestion cost.

Reference: [Primary documentation](https://opentelemetry.io/docs/specs/semconv/exceptions/exceptions-spans/).

### 3b. Boundaries and lifecycle

Unexpected failure → capture protected evidence → group → notify/triage → fix in a release → observe recurrence without revealing details to callers.

## 4. How to apply / implement / use it?

Save as `error_tracking_demo.py`; run `python3 error_tracking_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
import traceback
groups = {}
def capture(error, release):
    frames = traceback.extract_tb(error.__traceback__)
    location = frames[-1].name if frames else "unknown"
    fingerprint = (type(error).__name__, location)
    entry = groups.setdefault(fingerprint, {"count": 0, "releases": set()})
    entry["count"] += 1
    entry["releases"].add(release)
def divide(value):
    return 10 / value
for release in ("v1", "v2"):
    try:
        divide(0)
    except ZeroDivisionError as error:
        capture(error, release)
assert len(groups) == 1
assert next(iter(groups.values()))["count"] == 2
assert "v2" in next(iter(groups.values()))["releases"]
```

This offline grouping core deliberately excludes exception messages and local variables. A type/function fingerprint can merge distinct bugs and is not a production grouping algorithm. Real systems need privacy review, SDK configuration, access control, retention, and nonblocking transport.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not expose stack traces to clients, capture secrets from locals/request bodies, or report every expected validation rejection as an actionable defect.

## 6. How do I know I understand it?

**Blank-page check:** Explain fingerprint, occurrence, affected release, and regression. Diagnose both over-grouping and over-fragmentation.

| Constraint change | Predict the failure and response |
| --- | --- |
| An exception message contains a token | Do not include it by default; sanitize before transmission, not only after storage. |
| Tracker is unavailable | Bound buffering and drop safely according to policy; do not fail customer operations. |
