# Third-party API Integration

[Lesson index](../../README.md) · Previous: [Webhook](6.webhook.md) · Next: [Service-to-Service Communication](8.service_to_service_communication.md)

## 1. What is it?

A third-party API integration adapts an independently operated service into your application's workflow, like hiring an outside courier while keeping responsibility for your customer's delivery promise.

The provider owns its availability, limits, authentication, versioning, and data semantics. Your application still owns the boundary exposed to its callers.

## 2. Why do we need it?

Payments, messaging, identity, and shipping often need outside capabilities. Calling an SDK directly from every handler duplicates timeout/retry logic and spreads provider-specific types throughout business code.

Specific pain: a provider stalls, every API request waits indefinitely, retries amplify demand, and a provider credential failure is incorrectly returned as “your user must log in.”

## 3. Under the hood / mechanism / system flow

### 3a. Connections, deadlines, parsing, and retry amplification

A request can spend time in DNS, connection-pool wait, TCP/TLS, writes, response headers, and body reads. A socket read timeout may apply separately to each read; it is not automatically an end-to-end deadline. Reuse safe connection pools and bound concurrency/body size.

Retries add requests and can multiply across layers: three attempts at several nested services can create far more than three provider calls. Retry only selected transient outcomes when repeating the operation is safe, with bounded attempts, budget, backoff, and jitter. [AWS's timeout/retry guidance](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/) discusses these failure dynamics.

The cost of an integration includes network latency, quotas/billing, authentication/key refresh, serialization, response validation, and reconciliation. A successful HTTP code can still contain a malformed or semantically wrong body.

### 3b. Adapter and outcome boundary

```text
Application intent → provider adapter → fixed trusted endpoint/auth
    → bounded attempt(s) within remaining deadline → validate response
    → domain result or stable typed failure → application policy
```

Keep credentials server-owned and out of logs. Do not allow user-supplied arbitrary URLs/redirects to turn the client into an internal-network fetcher. Keep TLS verification enabled. Classify not-found, rejected input, provider auth/configuration failure, temporary unavailability, and protocol drift separately.

For writes, a timeout can occur after provider commit; do not blindly retry POST just because the transport raised. Use the provider's documented idempotency/reconciliation contract. Retry policy, provider version, response mapping, and failure metrics belong in one reviewed adapter rather than every caller.

## 4. How to apply / implement / use it?

Save as `third_party_integration_demo.py`; run `python3 third_party_integration_demo.py`. Standard library only. This GET-only adapter uses an injected fake transport, clock, sleep, and jitter; it performs **no network requests or real sleeps**.

The transport contract is to enforce the supplied remaining timeout and a bounded body read. A real HTTP library needs explicit connect/read/pool/total-budget configuration; these fake tests cannot prove that configuration or real TLS/provider compatibility.

```python
from dataclasses import dataclass
import json
import re

class ProviderUnavailable(Exception):
    pass

class ProviderAuthFailure(Exception):
    pass

class ProviderRejected(Exception):
    pass

class ProviderProtocolError(Exception):
    pass

@dataclass(frozen=True)
class Response:
    status: int
    headers: dict
    body: bytes

class Clock:
    def __init__(self):
        self.value = 0.0

    def __call__(self):
        return self.value

    def sleep(self, seconds):
        self.value += seconds

class FakeTransport:
    def __init__(self, events, clock):
        self.events = list(events)
        self.clock = clock
        self.calls = []

    def __call__(self, url, headers, timeout):
        self.calls.append((url, timeout))
        event = self.events.pop(0)
        if event == "timeout":
            self.clock.sleep(timeout)
            raise TimeoutError()
        self.clock.sleep(min(0.1, timeout))
        return event

def get_order(order_id, api_token, transport, clock, sleep, jitter):
    if not isinstance(order_id, str) or re.fullmatch(r"[A-Za-z0-9_-]{1,64}", order_id) is None:
        raise ValueError("INVALID_ORDER_ID")
    deadline = clock() + 5.0
    url = "https://partner.example.test/orders/" + order_id
    headers = {"Authorization": "Bearer " + api_token, "Accept": "application/json"}
    for attempt in range(3):
        remaining = deadline - clock()
        if remaining <= 0:
            raise ProviderUnavailable("DEADLINE_EXCEEDED")
        response = None
        try:
            response = transport(url, headers, timeout=min(2.0, remaining))
        except TimeoutError:
            pass
        if clock() >= deadline:
            raise ProviderUnavailable("DEADLINE_EXCEEDED")
        if response is not None:
            normalized_headers = {name.lower(): value for name, value in response.headers.items()}
            if response.status == 200:
                if len(response.body) > 16384 or normalized_headers.get("content-type", "").split(";")[0].strip().lower() != "application/json":
                    raise ProviderProtocolError("INVALID_RESPONSE")
                try:
                    body = json.loads(response.body.decode("utf-8"))
                except (UnicodeDecodeError, json.JSONDecodeError):
                    raise ProviderProtocolError("INVALID_RESPONSE") from None
                if not isinstance(body, dict) or body.get("order_id") != order_id or not isinstance(body.get("state"), str) or body["state"] not in {"accepted", "shipped"}:
                    raise ProviderProtocolError("INVALID_RESPONSE")
                return {"order_id": body["order_id"], "state": body["state"]}
            if response.status in {401, 403}:
                raise ProviderAuthFailure("PROVIDER_AUTH_CONFIGURATION")
            if response.status not in {429, 502, 503, 504}:
                raise ProviderRejected("PROVIDER_REJECTED_REQUEST")
        if attempt == 2:
            raise ProviderUnavailable("ATTEMPTS_EXHAUSTED")
        delay = jitter(0.5 * 2**attempt)
        if response is not None and "retry-after" in normalized_headers:
            retry = normalized_headers["retry-after"]
            if not isinstance(retry, str) or re.fullmatch(r"[0-9]{1,6}", retry) is None:
                raise ProviderProtocolError("UNSUPPORTED_RETRY_AFTER")
            delay = max(delay, int(retry))
        if delay >= deadline - clock():
            raise ProviderUnavailable("RETRY_EXCEEDS_BUDGET")
        sleep(delay)
    raise ProviderUnavailable("ATTEMPTS_EXHAUSTED")

success = Response(200, {"Content-Type": "application/json"}, b'{"order_id":"ord-1","state":"accepted"}')

def run(events):
    clock = Clock()
    transport = FakeTransport(events, clock)
    result = get_order("ord-1", "fixture-not-a-real-secret", transport, clock, clock.sleep, lambda upper: upper / 2)
    return result, transport, clock

result, transport, clock = run([Response(503, {}, b""), success])
assert result["state"] == "accepted" and len(transport.calls) == 2 and clock() < 5
result, transport, clock = run([Response(429, {"Retry-After": "2"}, b""), success])
assert len(transport.calls) == 2 and clock() >= 2
for events, expected in [
    ([Response(401, {}, b"private")], ProviderAuthFailure),
    ([Response(200, {"Content-Type": "application/json"}, b"broken")], ProviderProtocolError),
    (["timeout", "timeout", "timeout"], ProviderUnavailable),
]:
    try:
        run(events)
    except expected:
        pass
    else:
        raise AssertionError("Provider failure was hidden")
print("happy: bounded safe-read retry; unhappy: auth/protocol/timeout failures remain explicit")
```

This fixture accepts bounded integer delta-seconds for `Retry-After`; a general HTTP adapter must handle the applicable HTTP-date form too. It never retries sooner than that guidance; if the wait cannot fit, it stops. Production jitter must be a valid bounded nonnegative value and should vary callers' schedules rather than use this deterministic test function.

The full response is bounded by the transport before the body-size assertion; checking an already unbounded allocation would be too late. Add real provider sandbox/contract tests, secret rotation, connection limits, safe redirect policy, rate-limit coordination, and metrics. Preserve a safe public error contract rather than forwarding raw provider bodies or credential failures to clients unchanged.

## 5. When should I NOT use this? Trade-offs and anti-patterns

- Do not add a provider for a capability your bounded local implementation already handles well without the dependency.
- Do not retry authentication/validation failures or retry at every nested layer independently.
- Do not use unlimited timeouts, attempts, response bodies, or synchronous calls in a critical transaction.
- Do not return fabricated success or empty data to hide provider failure unless an explicit degraded-data contract permits it.
- Do not assume an SDK's defaults match your security, deadline, and retry requirements.

Vendor lock-in includes semantics and failure recovery, not just method names. A narrow adapter helps but does not eliminate migration or operational cost.

## 6. How do I know I understand it?

**Blank-page check:** define the provider request, trusted endpoint/auth, total deadline, attempts, repeat-safety evidence, response contract, error taxonomy, and reconciliation behavior.

| Constraint change | Predict the failure and response |
| --- | --- |
| Provider returns `401` | Investigate provider credentials/configuration; do not ask your end user to log in again automatically |
| Write times out after provider commit | Preserve uncertainty and reconcile/retry only under a safe identity contract |
| `Retry-After` exceeds remaining budget | Stop rather than ignore the wait or exceed the deadline |
| Every layer retries three times | Retry amplification can overwhelm the downstream service |
| Response becomes valid JSON with wrong fields | Protocol/schema validation must still reject it |

You understand integration when a provider's slowness, drift, and uncertain outcomes remain bounded and do not silently become your application's false promises.
