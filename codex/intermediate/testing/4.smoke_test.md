# Smoke Test

[Lesson index](../../README.md) · [Previous](3.regression_test.md) · [Next](5.load_test.md)

## 1. What is it?

A smoke test is a small critical-path check that a built or deployed system is usable enough for deeper testing, like checking the lights and engine before a long drive.

## 2. Why do we need it?

A successful build does not show the application boots, finds configuration, reaches required storage, or serves its most essential operation.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Smoke suites favor speed, representative wiring, and safe cleanup over broad coverage. Readiness checks and one isolated business probe answer different questions. Deployment gates need explicit failure behavior and must not create real customer side effects.

Reference: [Primary documentation](https://kubernetes.io/docs/tasks/configure-pod-container/configure-liveness-readiness-startup-probes/).

### 3b. Boundaries and lifecycle

Deploy candidate → verify startup/readiness → perform a safe critical probe → promote or stop rollout → investigate failure.

## 4. How to apply / implement / use it?

Save as `smoke_test_demo.py`; run `python3 smoke_test_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
def readiness(dependencies):
    return 200 if all(dependencies.values()) else 503
def smoke(probe):
    response = probe()
    if response != 200:
        raise AssertionError("candidate not ready")
smoke(lambda: readiness({"database": True, "config": True}))
try:
    smoke(lambda: readiness({"database": False, "config": True}))
except AssertionError:
    pass
else:
    raise AssertionError("bad rollout passed smoke")
```

This executable gate model uses injected dependency results, not a deployed service. A real smoke test must exercise the actual candidate endpoint and, where safe, an isolated critical operation. It must not charge cards or send real notifications.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not call a large slow regression suite smoke. A passing smoke test is not proof of performance, security, all migrations, or every feature.

## 6. How do I know I understand it?

**Blank-page check:** Choose three checks that would reject a badly wired release quickly. Explain what a passing result still cannot establish.

| Constraint change | Predict the failure and response |
| --- | --- |
| Health route returns static 200 | It proves routing, not required dependency readiness. |
| Probe mutates shared customer data | Replace it with isolated disposable fixtures or a read-only critical path. |
