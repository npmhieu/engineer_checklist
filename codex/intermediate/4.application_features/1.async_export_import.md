# Async Export / Import

[Lesson index](../../README.md) · [Previous](../3.async_background_processing/18.idempotent_consumer.md) · [Next](2.notification_architecture.md)

## 1. What is it?

Async export/import moves large data transfers into tracked background workflows, like leaving a copying order and collecting the finished bundle later.

## 2. Why do we need it?

Large transfers exceed request deadlines, exhaust memory, and leave users unsure which rows were imported after a partial failure.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Exports need an explicit consistency policy: snapshot, fixed watermark, or best-effort moving data. Imports need staged files, schema and business checks, stable row identity, bounded batches, and documented partial-success semantics. Store progress with completed effects, not before them.

Reference: [Primary documentation](https://learn.microsoft.com/en-us/azure/architecture/patterns/asynchronous-request-reply).

### 3b. Boundaries and lifecycle

Authorize and validate → persist job/input reference → process bounded chunks → publish a result or row-error artifact → expose tenant-scoped status and expiring download access.

## 4. How to apply / implement / use it?

Save as `async_export_import_demo.py`; run `python3 async_export_import_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
import csv
import io
def import_rows(raw):
    accepted, errors = {}, []
    for line, row in enumerate(csv.DictReader(io.StringIO(raw)), start=2):
        try:
            amount = int(row["amount"])
            if amount <= 0 or row["id"] in accepted:
                raise ValueError("positive amount and unique id required")
            accepted[row["id"]] = amount
        except (ValueError, KeyError) as error:
            errors.append((line, str(error)))
    return accepted, errors
accepted, errors = import_rows("id,amount\none,5\ntwo,-1\none,9\n")
assert accepted == {"one": 5}
assert [line for line, reason in errors] == [3, 4]
output = io.StringIO()
writer = csv.writer(output)
writer.writerow(["id", "amount"])
writer.writerows(accepted.items())
assert "one,5" in output.getvalue()
```

This is the bounded per-row transformation core, not an async server or durable checkpoint system. Input here is tiny and buffered; production must stream and cap file/row sizes. Exports intended for spreadsheets need formula-injection defenses for untrusted string cells.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not make small responses asynchronous without need. Avoid one giant transaction, unlimited row-error lists, unsafe spreadsheet cells, and retries that reinsert rows without stable keys.
