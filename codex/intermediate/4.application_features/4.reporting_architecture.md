# Reporting Architecture

[Lesson index](../../README.md) · [Previous](3.audit_activity_history.md) · [Next](5.batch_processing.md)

## 1. What is it?

Reporting architecture builds reliable read models for business questions, like maintaining a daily sales scoreboard separate from checkout.

## 2. Why do we need it?

Heavy scans slow operational writes, while undefined metric grain, joins, refunds, and late data produce convincing but incorrect totals.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Specify grain, units, time zone, fact ownership, and freshness. An incremental projection trades faster reads for update cost and lag. Stable fact identity supports duplicate-safe ingestion; late corrections need versioning or compensating facts, not blind append.

Reference: [Primary documentation](https://learn.microsoft.com/en-us/azure/architecture/patterns/materialized-view).

### 3b. Boundaries and lifecycle

Committed facts → ingestion/checkpoint → deduplicated projection → reconciled aggregates → authorized report; expose the data watermark with results.

## 4. How to apply / implement / use it?

Save as `reporting_architecture_demo.py`; run `python3 reporting_architecture_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
facts, totals = {}, {}
def ingest(event):
    event_id = event["id"]
    if event_id in facts:
        if facts[event_id] != event:
            raise ValueError("conflicting fact identity")
        return
    facts[event_id] = dict(event)
    day = event["day"]
    totals[day] = totals.get(day, 0) + event["cents"]
sale = {"id": "sale-1", "day": "2026-10-17", "cents": 900}
ingest(sale)
ingest(sale)
ingest({"id": "refund-1", "day": "2026-10-17", "cents": -200})
assert totals["2026-10-17"] == 700
try:
    ingest({**sale, "cents": 999})
except ValueError:
    pass
else:
    raise AssertionError("conflicting history accepted")
```

The dictionary projection models duplicate/correction semantics only. Production ingestion and checkpoint updates must be atomic or replay-safe; financial totals require validated currency, fact schema, tenant scope, and reconciliation.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not add a warehouse for a tiny indexed query. Do not let analytics share unlimited resources with checkout or confuse approximate/eventually consistent counts with transactional balances.

## 6. How do I know I understand it?

**Blank-page check:** Define a metric from raw facts, including refunds and late arrivals. Explain the watermark and a full rebuild verification.

| Constraint change | Predict the failure and response |
| --- | --- |
| An event arrives a day late | Recompute the affected business period according to occurrence-time policy. |
| Two currencies appear | Group or convert with explicit rate/time rules; adding raw cents is meaningless. |
