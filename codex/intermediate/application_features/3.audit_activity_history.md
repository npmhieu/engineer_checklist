# Audit / Activity History

[Lesson index](../../README.md) · [Previous](2.notification_architecture.md) · [Next](4.reporting_architecture.md)

## 1. What is it?

Audit/activity history records attributable changes over time, like a signed change ledger rather than a casual debug notebook.

## 2. Why do we need it?

Mutable rows show current state but cannot explain who changed access, whether a denied attempt occurred, or which committed change a customer disputes.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Define actor, action, subject, tenant, time, outcome, and a safe change summary. Transactional audit of successful writes differs from separately recorded failed attempts. Append-only application code is not tamper-proof against database administrators; stronger evidence needs access separation, protected retention, and integrity controls.

Reference: [Primary documentation](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html).

### 3b. Boundaries and lifecycle

Authorize → perform local mutation and success audit in one transaction → publish sanitized activity views; denied attempts use an independent safe evidence path.

## 4. How to apply / implement / use it?

Save as `audit_activity_history_demo.py`; run `python3 audit_activity_history_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
import sqlite3
database = sqlite3.connect(":memory:")
database.executescript("CREATE TABLE tasks(id PRIMARY KEY, title TEXT);"
                      "INSERT INTO tasks VALUES(1, 'old');"
                      "CREATE TABLE audit(actor TEXT, action TEXT, subject INTEGER);")
def rename(actor, title, fail=False):
    with database:
        database.execute("UPDATE tasks SET title=? WHERE id=1", (title,))
        if fail:
            raise RuntimeError("audit path failed")
        database.execute("INSERT INTO audit VALUES (?, 'rename', 1)", (actor,))
rename("user-1", "new")
try:
    rename("user-2", "lost", fail=True)
except RuntimeError:
    pass
assert database.execute("SELECT title FROM tasks").fetchone()[0] == "new"
assert database.execute("SELECT actor FROM audit").fetchall() == [("user-1",)]
database.close()
```

This real local transaction prevents a committed rename without its success record. Actor identity is a fixture, not user input to trust. The example omits failure-attempt logging, redaction, retention, export controls, and tamper-resistant storage.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not store passwords, tokens, full uploaded files, or every sensitive before/after value. Customer activity feeds, operational logs, and compliance evidence have different access and retention needs.

## 6. How do I know I understand it?

| Constraint change | Predict the failure and response |
| --- | --- |
| Transaction is rejected | Do not label the mutation successful; record a distinct denied/failed attempt if policy requires. |
| A database admin edits history | Ordinary append-only conventions cannot prove integrity against that actor. |
