# Basic Performance Test

[Lesson index](../../README.md) · [Previous](5.load_test.md) · [Next](../7.observability/1.structured_logging.md)

## 1. What is it?

A performance test measures resource or time cost for a defined operation, like weighing one packed box before testing the whole delivery fleet.

## 2. Why do we need it?

Functionally correct code can add full scans, repeated allocations, or extra round trips that become unacceptable as input grows.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Control workload and environment, verify equivalent results, warm up where appropriate, and measure repeated samples. Separate setup/build cost from lookup cost and include both when the actual workload rebuilds each time. Algorithmic work counts complement noisy wall-clock measurements.

Reference: [Primary documentation](https://docs.python.org/3/library/timeit.html).

### 3b. Boundaries and lifecycle

Choose operation and budget → build representative fixtures → assert correctness → measure repeated runs and memory/I/O → compare a recorded baseline on comparable environments.

## 4. How to apply / implement / use it?

Save as `basic_performance_test_demo.py`; run `python3 basic_performance_test_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
from timeit import repeat
records = [{"id": number, "value": number * 2} for number in range(2000)]
def scan(target):
    return next(row["value"] for row in records if row["id"] == target)
index = {row["id"]: row["value"] for row in records}
def indexed(target):
    return index[target]
assert scan(1999) == indexed(1999) == 3998
try:
    indexed(3000)
except KeyError:
    pass
else:
    raise AssertionError("missing key fabricated")
scan_samples = repeat(lambda: scan(1999), number=100, repeat=3)
index_samples = repeat(lambda: indexed(1999), number=100, repeat=3)
assert all(value >= 0 for value in scan_samples + index_samples)
print({"scan_best_seconds": min(scan_samples),
       "indexed_best_seconds": min(index_samples),
       "index_entries": len(index)})
```

This real microbenchmark excludes index construction and measures one worst-position lookup case. It makes no brittle speed-ratio assertion. A missing scan raises StopIteration while the index raises KeyError; a shared public API should normalize that difference.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not optimize from one noisy timing or benchmark only the happy path. An index spends memory and build/update time; one lookup may not justify building it.

## 6. How do I know I understand it?

**Blank-page check:** Explain O(n) scanning versus average O(1) dictionary lookup, including index construction, memory, and missing-data semantics.

| Constraint change | Predict the failure and response |
| --- | --- |
| Only one lookup runs | Index build cost can outweigh lookup savings. |
| Dataset exceeds memory | Measure memory and use a suitable database/index or streaming strategy. |
