# Dead Letter Queue Strategy

[Lesson index](../../README.md) · [Previous](8.advanced_retry_strategies.md) · [Next](10.queue_backpressure.md)

## 1. What is it?

A DLQ strategy defines investigation, retention, repair, and controlled redrive for failed messages, like an owned case-management process rather than an abandoned tray.

## 2. Why do we need it?

A queue of failures without owners or safe replay tools becomes silent data loss, a privacy archive, or a future replay storm.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Record original identity, reason category, attempts, source, schema, and protected payload reference. Define retention, access, oldest-age alarms, and transfer guarantees. Redrive preserves operation identity and targets a verified fix with bounded rate and audit evidence.

Reference: [Primary documentation](https://www.rabbitmq.com/docs/dlx).

### 3b. Boundaries and lifecycle

Quarantine reliably → notify owner → inspect safely → approve repair/redrive → replay in a limited cohort → verify outcomes → close or retain under policy.

## 4. How to apply / implement / use it?

Save as `dead_letter_queue_strategy_demo.py`; run `python3 dead_letter_queue_strategy_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
dead = {"evt-1": {"reason": "schema", "fixed": False}}
redriven = []
def redrive(event_id, authorized, capacity):
    if not authorized:
        raise PermissionError("redrive denied")
    entry = dead[event_id]
    if not entry["fixed"] or capacity <= 0:
        raise ValueError("unsafe redrive")
    redriven.append(event_id)
    del dead[event_id]
try:
    redrive("evt-1", True, 1)
except ValueError:
    pass
assert "evt-1" in dead
dead["evt-1"]["fixed"] = True
redrive("evt-1", True, 1)
assert redriven == ["evt-1"] and not dead
```

This single-process model demonstrates approval/preconditions. Production must not delete DLQ data before a reliable handoff; durable redrive state and broker-specific transfer guarantees are required. Authorization is an injected fixture.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not blindly redrive every failure or modify IDs to evade deduplication. Keep sensitive payloads protected and avoid infinite retention without policy.

## 6. How do I know I understand it?

**Blank-page check:** Write a runbook covering ownership, safety checks, replay rate, partial failure, and evidence of repaired outcomes.

| Constraint change | Predict the failure and response |
| --- | --- |
| The destination is down during redrive | Keep recoverable ownership until confirmed safe transfer; do not lose the original. |
| Fix changes event semantics | Use an audited correction contract rather than silently rewriting historical facts. |
