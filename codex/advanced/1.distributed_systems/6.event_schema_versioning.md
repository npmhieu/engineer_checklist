# Event Schema / Versioning

[Lesson index](../../README.md) · [Previous](5.event_driven_architecture_at_scale.md) · [Next](7.event_ordering.md)

## 1. What is it?

Event schema/versioning defines and evolves fact contracts, like adding a compatible field to a shared form without changing what old entries mean.

## 2. Why do we need it?

A producer can deploy valid JSON that silently breaks old consumers or reinterprets archived events during replay.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Specify types, required/optional fields, defaults, units, and semantic meaning. Backward compatibility asks whether new readers can read old data; forward asks whether old readers can read new data; transitive checks include retained historical versions. Rules depend on serialization format, not version numbers alone.

Reference: [Primary documentation](https://avro.apache.org/docs/1.12.0/specification/).

### 3b. Boundaries and lifecycle

Design change → check reader/writer compatibility and semantics → deploy tolerant readers/adapters → publish new form → retain old decoding paths for replay.

## 4. How to apply / implement / use it?

Save as `event_schema_versioning_demo.py`; run `python3 event_schema_versioning_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
def upcast(event):
    if event["version"] == 1:
        return {"version": 2, "id": event["id"], "cents": event["cents"],
                "currency": "USD"}
    if event["version"] == 2:
        return dict(event)
    raise ValueError("unsupported schema")
old = {"version": 1, "id": "evt-1", "cents": 500}
assert upcast(old)["currency"] == "USD"
assert old["version"] == 1
try:
    upcast({"version": 9})
except ValueError:
    pass
else:
    raise AssertionError("unknown schema interpreted")
```

This explicit upcaster assumes the historical v1 contract guaranteed USD. It is not safe to invent that default without evidence. It does not implement an Avro reader, registry, full validation, or automatic semantic compatibility.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not change cents into dollars under the same field or delete historical decoders while replay remains supported. Version labels do not excuse incompatible semantics.

## 6. How do I know I understand it?

**Blank-page check:** Draw old/new writer and reader combinations. Explain why an optional field can still create a business-level breaking change.

| Constraint change | Predict the failure and response |
| --- | --- |
| Old events used multiple undocumented currencies | A default cannot repair missing meaning; investigate and migrate with domain evidence. |
| Only latest-version compatibility is checked | An older retained event may still fail; evaluate transitive/replay requirements. |
