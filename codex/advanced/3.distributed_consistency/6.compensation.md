# Compensation

[Lesson index](../../README.md) · [Previous](5.saga_pattern.md) · [Next](7.distributed_locking.md)

## 1. What is it?

Compensation is a new business action that semantically offsets a previous committed action, like issuing a refund rather than erasing a completed payment.

## 2. Why do we need it?

Restoring an old snapshot can overwrite legitimate intervening changes and cannot undo external real-world effects.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Define compensation using domain intent and stable identity. A refund, release, or cancellation may be partial, time-limited, fee-bearing, or impossible. It needs its own authorization, audit, retries, and completion tracking; reverse order is common but dependency policy decides.

Reference: [Primary documentation](https://learn.microsoft.com/en-us/azure/architecture/patterns/compensating-transaction).

### 3b. Boundaries and lifecycle

Observe failure → determine valid compensating action from original outcome/current state → execute idempotently → record result or unresolved liability.

## 4. How to apply / implement / use it?

Save as `compensation_demo.py`; run `python3 compensation_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
balance = 100
refunded = set()
balance -= 20
balance += 7
def refund(original_payment):
    global balance
    if original_payment in refunded:
        return "duplicate"
    balance += 20
    refunded.add(original_payment)
    return "refunded"
assert refund("payment-1") == "refunded"
assert balance == 107
assert refund("payment-1") == "duplicate"
assert balance == 107
assert balance != 100
```

This arithmetic model preserves an intervening credit and illustrates duplicate-safe intent only in memory. Production needs durable atomic refund identity/balance coordination or provider-supported idempotency, not this set.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not restore a stale pre-operation value or call compensation a rollback. Some effects, such as a sent email or shipped parcel, cannot be erased.

## 6. How do I know I understand it?

**Blank-page check:** Explain why refunding a debit is different from restoring an account snapshot after other transactions.

| Constraint change | Predict the failure and response |
| --- | --- |
| A refund incurs a fee | Compensation is a business outcome with its own accounting, not an exact inverse. |
| Refund response disappears | Reconcile by original payment/refund identity before creating another refund. |
