# Advanced Alerting

[Lesson index](../../README.md) · [Previous](5.capacity_monitoring.md) · [Next](7.chaos_testing.md)

## 1. What is it?

Advanced alerting combines impact, sustained evidence, routing, and burn-rate policy to page on actionable reliability risk, like distinguishing a spreading fire from one noisy sensor.

## 2. Why do we need it?

Static thresholds page too often during harmless spikes or too late during fast budget exhaustion.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Multiwindow burn alerts require both long-window impact and short-window persistence; thresholds depend on SLO/window and desired budget spend. Group/inhibit related symptoms, route to owners, and detect missing telemetry/delivery failures separately. Low traffic needs special sample policies.

Reference: [Primary documentation](https://sre.google/workbook/alerting-on-slos/).

### 3b. Boundaries and lifecycle

Evaluate trusted indicators → compute burn in aligned windows → apply severity and persistence → group/route → act via runbook → resolve and review.

## 4. How to apply / implement / use it?

Save as `advanced_alerting_demo.py`; run `python3 advanced_alerting_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
def page(long_error_fraction, short_error_fraction, target, enough_samples):
    if not 0 < target < 1:
        raise ValueError("invalid SLO")
    if not enough_samples:
        return False
    allowed = 1 - target
    return long_error_fraction / allowed > 10 and short_error_fraction / allowed > 10
assert page(0.02, 0.02, 0.999, True)
assert not page(0.02, 0.0001, 0.999, True)
assert not page(0.02, 0.02, 0.999, False)
try:
    page(0.02, 0.02, 1.0, True)
except ValueError:
    pass
else:
    raise AssertionError("undefined burn accepted")
```

This two-window toy gate uses an illustrative 10x threshold, not a universal alert recommendation. It does not calculate windows, validate fractions, route pages, or monitor telemetry loss. Insufficient samples need a separate policy, not silent permanent suppression.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not copy burn thresholds without matching the objective/window or page every replica for one dependency outage. Test expression logic and notification delivery.

## 6. How do I know I understand it?

**Blank-page check:** Derive a burn threshold from acceptable budget spend and detection time, then explain why both windows matter.

| Constraint change | Predict the failure and response |
| --- | --- |
| Long window is bad but short window recovered | Suppressing a page may be appropriate while a ticket/trend still records damage. |
| Traffic is tiny but every request fails | Use a low-traffic/synthetic-probe strategy rather than only large-sample burn rules. |
