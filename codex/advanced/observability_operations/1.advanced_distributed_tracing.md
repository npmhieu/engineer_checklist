# Advanced Distributed Tracing

[Lesson index](../../README.md) · [Previous](../performance/7.large_scale_caching.md) · [Next](2.service_level_objectives.md)

## 1. What is it?

Advanced distributed tracing models causal work across retries, batches, queues, and sampled fleets, like reconstructing a journey with branches and delayed transfers rather than one straight line.

## 2. Why do we need it?

Simple parent-child traces misrepresent batch consumers, retries, long-running async work, and missing sampled evidence.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Use spans for attempts, links for relevant nonparent causal relationships, and bounded attributes. Head sampling decides early; tail sampling needs buffering/coordination to decide from completed evidence. Async delays, clock skew, dropped spans, and sensitive baggage limit conclusions; propagate approved context independently of authorization.

Reference: [Primary documentation](https://opentelemetry.io/docs/specs/otel/trace/api/).

### 3b. Boundaries and lifecycle

Extract validated context → create attempt/processing spans and links → propagate across carriers → finish/export with limits → sample/store → analyze critical paths and missing evidence.

## 4. How to apply / implement / use it?

Save as `advanced_distributed_tracing_demo.py`; run `python3 advanced_distributed_tracing_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
trace = "1" * 32
events = [{"id": "evt-1", "trace_id": trace, "span_id": "2" * 16},
          {"id": "evt-2", "trace_id": "3" * 32, "span_id": "4" * 16}]
batch_span = {"trace_id": "5" * 32, "span_id": "6" * 16, "links": []}
for event in events:
    batch_span["links"].append((event["trace_id"], event["span_id"]))
assert len(batch_span["links"]) == 2
assert batch_span["trace_id"] not in {event["trace_id"] for event in events}
def retain(completed_trace, capacity):
    if capacity <= 0:
        return False
    return completed_trace["error"] or completed_trace["duration_ms"] > 500
assert retain({"error": True, "duration_ms": 20}, 1)
assert not retain({"error": True, "duration_ms": 20}, 0)
```

This offline link/tail-policy model does not create OpenTelemetry spans or implement a collector. It intentionally exposes the capacity limit: even a desirable error trace can be dropped. Use maintained SDKs/propagators and collector configuration for real tracing.

Sampling reference: [OpenTelemetry sampling concepts](https://opentelemetry.io/docs/concepts/sampling/).

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not attach every payload/ID as indexed attributes or claim complete audit evidence from sampled traces. Unbounded tail buffers can become an outage source.

## 6. How do I know I understand it?

**Blank-page check:** Draw two messages feeding one batch and a retried attempt; justify parents versus links and the sampling policy.

| Constraint change | Predict the failure and response |
| --- | --- |
| Tail collector runs out of memory | Bound buffers and document drops; 'keep all errors' is not an unconditional guarantee. |
| Baggage crosses an untrusted boundary | Validate/drop sensitive or unbounded fields; tracing context is not a security principal. |
