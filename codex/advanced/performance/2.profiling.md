# Profiling

[Lesson index](../../README.md) · [Previous](1.performance_engineering.md) · [Next](3.capacity_planning.md)

## 1. What is it?

Profiling measures where execution time, allocations, or waits occur, like tracing which station consumes time on an assembly line.

## 2. Why do we need it?

Guessing at hot code wastes effort and can optimize a cheap function while most time is spent waiting for I/O.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Deterministic profilers instrument calls; sampling profilers periodically observe stacks; allocation and wall/CPU profiles answer different questions. Inclusive/cumulative time includes callees, while self time does not. Instrumentation and sampling have bias/overhead, so compare against an unprofiled baseline.

Reference: [Primary documentation](https://docs.python.org/3.12/library/profile.html).

### 3b. Boundaries and lifecycle

Capture representative workload → inspect hot paths/call counts/waits → form a hypothesis → measure a focused change → confirm end-to-end effect.

## 4. How to apply / implement / use it?

Save as `profiling_demo.py`; run `python3 profiling_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
import cProfile
import pstats
import io
def scan(limit):
    if limit < 1:
        raise ValueError("positive workload required")
    return sum(number * number for number in range(limit))
profiler = cProfile.Profile()
profiler.enable()
try:
    result = scan(2000)
    try:
        scan(0)
    except ValueError:
        pass
    else:
        raise AssertionError("invalid workload accepted")
finally:
    profiler.disable()
assert result == sum(number * number for number in range(2000))
entries = profiler.getstats()
assert any(getattr(entry.code, "co_name", "") == "scan" for entry in entries)
output = io.StringIO()
pstats.Stats(profiler, stream=output).sort_stats("cumulative").print_stats(5)
assert "scan" in output.getvalue()
assert not any(getattr(entry.code, "co_name", "") == "not_executed" for entry in entries)
print(output.getvalue())
```

This real cProfile example is compatible with the tested Python 3.12 runtime. It profiles a tiny CPU workload, not database/network waits or production load, and does not assert noisy timing ratios.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not enable high-overhead tracing across all production traffic without evaluation, or assume an empty profile means no bottleneck. Profiles can expose sensitive paths/arguments depending on tooling.

## 6. How do I know I understand it?

**Blank-page check:** Explain self versus cumulative time and CPU time versus wall time. Choose a profiler for CPU, allocation, and I/O-wait questions.

| Constraint change | Predict the failure and response |
| --- | --- |
| CPU is low but latency is high | Investigate waits, queues, lock contention, and dependencies rather than only CPU hotspots. |
| Profiled run is much slower | Account for measurement overhead and validate improvements without the profiler. |
