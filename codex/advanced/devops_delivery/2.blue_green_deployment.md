# Blue-Green Deployment

[Lesson index](../../README.md) · [Previous](1.infrastructure_as_code.md) · [Next](3.canary_deployment.md)

## 1. What is it?

Blue-green deployment prepares a second environment and switches traffic between old and new versions, like opening a fully checked replacement checkout area before closing the old one.

## 2. Why do we need it?

In-place replacement can leave mixed broken instances and slow recovery when the candidate does not start or integrate correctly.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Keep two sufficiently equivalent environments, validate the inactive one, then change routing. Connections, caches, sessions, background workers, and shared database compatibility outlive the switch. Retaining old compute costs capacity; switching back cannot reverse incompatible data or external effects.

Reference: [Primary documentation](https://argo-rollouts.readthedocs.io/en/stable/features/bluegreen/).

### 3b. Boundaries and lifecycle

Deploy green while blue serves → verify readiness/integration → approve switch → route new traffic → drain old connections/work → observe → retain rollback option within compatibility window.

## 4. How to apply / implement / use it?

Save as `blue_green_deployment_demo.py`; run `python3 blue_green_deployment_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
environments = {"blue": {"version": "v1", "ready": True},
                "green": {"version": "v2", "ready": False}}
active = "blue"
def switch(target):
    global active
    if not environments[target]["ready"]:
        raise RuntimeError("target not ready")
    active = target
try:
    switch("green")
except RuntimeError:
    pass
assert active == "blue"
environments["green"]["ready"] = True
switch("green")
assert active == "green"
switch("blue")
assert active == "blue"
```

This routing-state model does not create environments or switch real traffic. It assumes schema/config compatibility; a ready Boolean does not prove business correctness or make already-open connections move.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not switch incompatible database writers, run duplicate schedulers without ownership, or destroy blue before the rollback window ends. Capacity cost can approach two environments.

## 6. How do I know I understand it?

**Blank-page check:** Draw traffic, shared data, in-flight connections, and worker ownership before and after the switch.

| Constraint change | Predict the failure and response |
| --- | --- |
| Green writes a new unsupported enum | Blue may no longer be a safe rollback even if its containers still run. |
| Long-lived clients remain connected to blue | Drain/expiry and compatibility policy must cover them; routing changes are not instant migration. |
