# Progressive Delivery

[Lesson index](../../README.md) · [Previous](3.canary_deployment.md) · [Next](5.advanced_feature_flags.md)

## 1. What is it?

Progressive delivery expands exposure through controlled stages using evidence and policy, like opening more lanes only after each trial passes agreed checks.

## 2. Why do we need it?

Manual rollout percentages without automated holds, ownership, and reliable evidence let unhealthy versions spread or stall unnoticed.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Combine artifact identity, traffic/config stages, analysis, approval, pause/abort, and rollback compatibility. Controllers reconcile desired rollout state, but metric-provider outages and inconclusive evidence need explicit hold policy. Deployment and feature exposure can be separate dimensions.

Reference: [Primary documentation](https://argo-rollouts.readthedocs.io/en/stable/features/analysis/).

### 3b. Boundaries and lifecycle

Verify candidate → expose first stage → collect sufficient fresh evidence → approve next bounded stage → abort/hold on policy → complete and clean up.

## 4. How to apply / implement / use it?

Save as `progressive_delivery_demo.py`; run `python3 progressive_delivery_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
stages = [1, 10, 50, 100]
state = {"weight": 1, "aborted": False}
def advance(verdict):
    if state["aborted"]:
        raise RuntimeError("rollout already aborted")
    if verdict == "inconclusive":
        return state["weight"]
    if verdict == "fail":
        state.update(weight=0, aborted=True)
        return 0
    if verdict != "pass":
        raise ValueError("unknown verdict")
    index = stages.index(state["weight"])
    state["weight"] = stages[min(index + 1, len(stages) - 1)]
    return state["weight"]
assert advance("inconclusive") == 1
assert advance("pass") == 10
assert advance("fail") == 0
try:
    advance("pass")
except RuntimeError:
    pass
else:
    raise AssertionError("aborted rollout resumed silently")
```

This state-machine model does not deploy or analyze real metrics. Actual abort may require an orchestrator, traffic manager, flag change, or forward recovery; it does not undo committed effects.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not auto-promote when telemetry is missing or treat rollback as universally safe after a schema/data change. Avoid staged rollout without a named owner and maximum hold policy.

## 6. How do I know I understand it?

**Blank-page check:** Draw stages, evidence freshness, approval, hold/abort, and recovery paths; identify every irreversible boundary.

| Constraint change | Predict the failure and response |
| --- | --- |
| Metric provider is unavailable | Hold and investigate under policy rather than interpret unknown as pass. |
| Feature flag enables code outside the canary cohort | Exposure can exceed intended blast radius; coordinate rollout dimensions. |
