# Queue Backpressure

[Lesson index](../../README.md) · [Previous](9.dead_letter_queue_strategy.md) · [Next](../distributed_consistency/1.eventual_consistency.md)

## 1. What is it?

Queue backpressure slows or rejects intake when downstream capacity is exhausted, like stopping new orders when the workshop's safe backlog is full.

## 2. Why do we need it?

An unbounded queue converts overload into memory/disk exhaustion and deadlines that expire before work begins.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Bound outstanding messages and bytes, prefetch, worker concurrency, and age. High/low watermarks avoid rapid pause/resume flapping. Backpressure must reach producers or admission control; merely moving backlog into another buffer does not remove it.

Reference: [Primary documentation](https://www.rabbitmq.com/docs/consumer-prefetch).

### 3b. Boundaries and lifecycle

Measure occupancy/age → pause pulls or reject/defer admission → drain active work → resume below a safe watermark → observe throughput and deadlines.

## 4. How to apply / implement / use it?

Save as `queue_backpressure_demo.py`; run `python3 queue_backpressure_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
state = {"paused": False}
def can_pull(depth):
    if depth >= 4:
        state["paused"] = True
    elif depth <= 1:
        state["paused"] = False
    return not state["paused"]
assert can_pull(0)
assert not can_pull(4)
assert not can_pull(3)
assert not can_pull(2)
assert can_pull(1)
def admit(depth, limit=5):
    if depth >= limit:
        raise OverflowError("queue full")
    return depth + 1
assert admit(4) == 5
try:
    admit(5)
except OverflowError:
    pass
else:
    raise AssertionError("overload admitted")
```

This hysteresis/admission model does not control a broker client or reserve capacity atomically. Production should bound bytes and age too, with an explicit reject/defer/drop policy appropriate to the workload.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not use infinite disk or unbounded prefetch as a capacity plan. Dropping critical work silently is not graceful backpressure.
