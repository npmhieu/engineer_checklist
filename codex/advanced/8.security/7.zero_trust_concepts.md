# Zero Trust Concepts

[Lesson index](../../README.md) · [Previous](6.advanced_api_security.md) · [Next](8.dependency_supply_chain_security.md)

## 1. What is it?

Zero trust treats access as an explicit, least-privilege policy decision rather than trusting network location, like checking authorization for each protected room even inside headquarters.

## 2. Why do we need it?

Compromised internal workloads or stolen sessions can move laterally when inside-the-network implicitly means allowed.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Combine verified subject/workload identity, resource/action policy, device/workload posture where relevant, short-lived evidence, and continuous policy/telemetry. Enforcement occurs at defined access boundaries; an authenticated encrypted channel is necessary in many designs but does not grant unlimited authority.

Reference: [Primary documentation](https://csrc.nist.gov/pubs/sp/800/207/final).

### 3b. Boundaries and lifecycle

Verify identity evidence → evaluate current resource policy/context → establish narrowly scoped access → observe/re-evaluate on defined changes → revoke or deny when evidence is insufficient.

## 4. How to apply / implement / use it?

Save as `zero_trust_concepts_demo.py`; run `python3 zero_trust_concepts_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
def authorize(identity, resource, now):
    if not identity["verified"] or now >= identity["expires"]:
        raise PermissionError("invalid identity evidence")
    if identity["revoked"] or resource not in identity["allowed"]:
        raise PermissionError("policy denied")
    return True
identity = {"verified": True, "expires": 20, "revoked": False,
            "allowed": {"reports:read"}}
assert authorize(identity, "reports:read", 10)
try:
    authorize(identity, "payments:write", 10)
except PermissionError:
    pass
else:
    raise AssertionError("network trust bypass")
identity["revoked"] = True
try:
    authorize(identity, "reports:read", 10)
except PermissionError:
    pass
else:
    raise AssertionError("revocation ignored")
```

This deterministic policy model assumes verified evidence and fresh policy inputs. It is not token verification, a zero-trust product, or proof that revocation propagates instantly to every cache and established session.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not buy a network appliance and declare zero trust complete, or disable access controls for private addresses. Avoid unlimited central synchronous policy dependencies without resilience planning.
