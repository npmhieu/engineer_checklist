# Secrets Management

[Lesson index](../../README.md) · [Previous](2.threat_modeling.md) · [Next](4.encryption.md)

## 1. What is it?

Secrets management controls issuance, access, rotation, revocation, and safe handling of credentials, like a managed key office rather than keys copied into notebooks.

## 2. Why do we need it?

Credentials committed to source, reused across environments, or never rotated remain usable long after accidental disclosure.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Use workload identity to access a dedicated secret authority with least privilege, audit, expiry, and rotation. Prefer short-lived scoped credentials where supported. Retrieval availability, cache TTL, deployment reload, and old/new overlap matter; environment variables and base64 are delivery/encoding choices, not a secret vault.

Reference: [Primary documentation](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html).

### 3b. Boundaries and lifecycle

Authenticate workload → authorize secret scope → obtain bounded-lifetime value → use without logging → refresh/rotate → revoke old credentials and verify callers recover.

## 4. How to apply / implement / use it?

Save as `secrets_management_demo.py`; run `python3 secrets_management_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
secrets = {"database": {"value": "fixture-only", "expires": 20, "version": 1}}
def fetch(workload, name, now):
    if workload != "orders-worker" or name != "database":
        raise PermissionError("secret access denied")
    entry = secrets[name]
    if now >= entry["expires"]:
        raise PermissionError("credential expired")
    return entry["value"], entry["version"]
assert fetch("orders-worker", "database", 10)[1] == 1
try:
    fetch("analytics", "database", 10)
except PermissionError:
    pass
else:
    raise AssertionError("secret scope bypassed")
try:
    fetch("orders-worker", "database", 20)
except PermissionError:
    pass
else:
    raise AssertionError("expired credential accepted")
secrets["database"].update(value="rotated-fixture", expires=40, version=2)
assert fetch("orders-worker", "database", 21)[1] == 2
```

This in-memory fixture is not a secret store and contains no real credential. Production needs verified workload identity, protected transport/storage, access audit, revocation behavior, and a tested reload/overlap strategy.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not put secrets in repository history, images, telemetry, command arguments, or broadly readable files. Do not make secret-manager outage trigger an insecure hard-coded fallback.

## 6. How do I know I understand it?

**Blank-page check:** Explain bootstrap identity, scope, expiry, rotation overlap, cache behavior, and revocation for one database credential.

| Constraint change | Predict the failure and response |
| --- | --- |
| Secret rotates but clients keep old connections | Coordinate connection renewal and overlap/revocation rather than assuming config reload updates established sessions. |
| A value leaks into logs | Revoke/rotate and investigate exposure; deleting one log line is not sufficient containment. |
