# Security Architecture

[Lesson index](../../README.md) · [Previous](../7.observability_operations/7.chaos_testing.md) · [Next](2.threat_modeling.md)

## 1. What is it?

Security architecture assigns trust boundaries and layered controls to protect defined assets, like designing locks, access rules, and fire compartments before furnishing a building.

## 2. Why do we need it?

Scattered authentication checks do not prevent cross-tenant access, compromised workloads, secret exposure, or unsafe recovery paths.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Identify assets, actors, data flows, trust boundaries, and abuse cases. Enforce identity, resource authorization, least privilege, safe input/output, encryption, audit, dependency security, and incident recovery at responsible layers. Defense in depth limits blast radius but adds configuration, operational cost, and failure modes.

Reference: [Primary documentation](https://cheatsheetseries.owasp.org/cheatsheets/Microservices_Security_Cheat_Sheet.html).

### 3b. Boundaries and lifecycle

Untrusted input → verified identity → action/resource/tenant authorization → bounded application work → least-privilege persistence/provider access → redacted evidence and recovery.

## 4. How to apply / implement / use it?

Save as `security_architecture_demo.py`; run `python3 security_architecture_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
records = {"task-1": {"tenant": "shop-1", "owner": "user-1"}}
def read_task(principal, task_id):
    record = records.get(task_id)
    if record is None:
        raise LookupError("not found")
    if principal["tenant"] != record["tenant"] or principal["user"] != record["owner"]:
        raise PermissionError("access denied")
    return dict(record)
assert read_task({"tenant": "shop-1", "user": "user-1"}, "task-1")["owner"] == "user-1"
try:
    read_task({"tenant": "shop-2", "user": "user-1"}, "task-1")
except PermissionError:
    pass
else:
    raise AssertionError("tenant boundary bypassed")
```

This real policy check assumes principal was already created from verified identity evidence. It is not authentication, a secure API, or a complete architecture. A production adapter must map missing/denied responses according to anti-enumeration policy and enforce storage-level scope too.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not design security as a final middleware checkbox or invent custom cryptographic/authentication protocols. Controls need threat-specific purpose, ownership, tests, and usable recovery.

## 6. How do I know I understand it?

**Blank-page check:** Draw one request across trust boundaries and identify the asset, control, failure policy, and residual risk at each crossing.

| Constraint change | Predict the failure and response |
| --- | --- |
| Application service account is compromised | Least-privilege database/provider scope and segmentation limit damage; end-user checks alone are insufficient. |
| A recovery environment is opened | Apply identity, secrets, audit, and data controls there too; emergencies do not erase trust boundaries. |
