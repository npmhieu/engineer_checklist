# Circuit Breaker

[Lesson index](../../README.md) · [Previous](../4.database_scaling/7.large_scale_data_architecture.md) · [Next](2.bulkhead.md)

## 1. What is it?

A circuit breaker temporarily rejects calls to an unhealthy dependency and probes recovery, like an electrical breaker interrupting a failing circuit.

## 2. Why do we need it?

Repeated slow calls and retries consume threads, connections, and capacity during a dependency outage.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Closed permits calls; open rejects; half-open permits limited recovery probes. Track classified failures over a defined policy/window and bound probe concurrency. A breaker does not replace deadlines, bulkheads, or idempotency, and local breakers across replicas need deliberate coordination or acceptable independence.

Reference: [Primary documentation](https://learn.microsoft.com/en-us/azure/architecture/patterns/circuit-breaker).

### 3b. Boundaries and lifecycle

Call while closed → observe failures → open for cooldown → allow limited probe → close on sufficient recovery or reopen on failure.

## 4. How to apply / implement / use it?

Save as `circuit_breaker_demo.py`; run `python3 circuit_breaker_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
state = {"failures": 0, "until": 0, "open": False}
def invoke(now, healthy):
    if state["open"] and now < state["until"]:
        raise ConnectionError("circuit open")
    probe = state["open"]
    if healthy:
        state.update(failures=0, until=0, open=False)
        return "ok"
    state["failures"] += 1
    if probe or state["failures"] >= 2:
        state.update(open=True, until=now + 10)
    raise TimeoutError("dependency failed")
assert invoke(0, True) == "ok"
for instant in (1, 2):
    try:
        invoke(instant, False)
    except TimeoutError:
        pass
try:
    invoke(3, True)
except ConnectionError:
    pass
else:
    raise AssertionError("cooldown bypassed")
assert invoke(12, True) == "ok"
```

This fake-clock sequential breaker uses consecutive failures rather than a rolling failure-rate window. It does not enforce concurrent half-open probe limits; production must add those atomically or use a maintained implementation.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not open on normal validation errors or use a breaker as a substitute for a useful fallback/fail-fast policy. Poor thresholds can flap or delay recovery.
