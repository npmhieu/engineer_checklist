# Latency Optimization

[Lesson index](../../README.md) · [Previous](5.throughput_optimization.md) · [Next](7.large_scale_caching.md)

## 1. What is it?

Latency optimization reduces time to a correct result across the full critical path, like shortening the slowest handoff in a customer's journey.

## 2. Why do we need it?

Fast average processing can hide queue waits, cold starts, sequential remote calls, and rare slow operations that dominate user experience.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Measure end-to-end distributions including queueing and failures. Optimize critical-path dependencies, connection reuse, query count, and variance. Parallel independent calls trade latency for resource demand; do not add or average component percentiles as if they were individual request durations.

Reference: [Primary documentation](https://sre.google/sre-book/handling-overload/).

### 3b. Boundaries and lifecycle

Trace representative slow requests → identify critical waits/work → remove or overlap safe dependencies → enforce budgets → remeasure tails under realistic load.

## 4. How to apply / implement / use it?

Save as `latency_optimization_demo.py`; run `python3 latency_optimization_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
import math
def percentile(values, quantile):
    if not values or not 0 < quantile <= 1:
        raise ValueError("invalid percentile input")
    ordered = sorted(values)
    return ordered[math.ceil(quantile * len(ordered)) - 1]
samples = [10] * 98 + [1000] * 2
assert sum(samples) / len(samples) < 30
assert percentile(samples, 0.99) == 1000
sequential_ms = 20 + 80 + 70
parallel_independent_ms = 20 + max(80, 70)
assert parallel_independent_ms < sequential_ms
try:
    percentile([], 0.99)
except ValueError:
    pass
else:
    raise AssertionError("empty latency evidence")
```

This nearest-rank distribution/critical-path calculation is not a real latency benchmark. The overlap assumes two independent operations and no added contention; production must measure actual scheduling and resource cost.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not parallelize dependent writes, hedge unsafe effects, or remove correctness/security checks to meet a timing target. Low averages are not evidence of healthy tails.

## 6. How do I know I understand it?

**Blank-page check:** Draw a request DAG and identify the critical path, queueing, and p99 evidence without summing percentiles.

| Constraint change | Predict the failure and response |
| --- | --- |
| Parallel calls saturate a shared pool | Queueing can erase the expected gain and worsen tails. |
| Failures return quickly | Include error rate and correct completion, not only a faster response histogram. |
