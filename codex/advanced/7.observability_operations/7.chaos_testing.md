# Chaos Testing

[Lesson index](../../README.md) · [Previous](6.advanced_alerting.md) · [Next](../8.security/1.security_architecture.md)

## 1. What is it?

Chaos testing deliberately introduces bounded faults to test a reliability hypothesis, like a supervised emergency drill rather than random damage.

## 2. Why do we need it?

Untested failover, timeout, and recovery assumptions often fail during the first real incident.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Define steady-state user outcomes, hypothesis, smallest fault/blast radius, authorization, abort conditions, observability, rollback, and cleanup. Start in controlled environments and expand only with evidence. A successful drill covers the tested fault/workload, not all failures.

Reference: [Primary documentation](https://principlesofchaos.org/).

### 3b. Boundaries and lifecycle

Establish baseline → approve bounded experiment → inject one controlled fault → observe invariants → abort if limits break → remove fault → verify recovery and record learning.

## 4. How to apply / implement / use it?

Save as `chaos_testing_demo.py`; run `python3 chaos_testing_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
def service(primary_available):
    return {"result": "ok", "path": "primary" if primary_available else "backup"}
def experiment(approved, scope):
    if not approved or scope != "local-fixture":
        raise PermissionError("experiment not authorized")
    baseline = service(True)
    during = service(False)
    recovered = service(True)
    assert baseline["result"] == during["result"] == recovered["result"] == "ok"
    assert during["path"] == "backup" and recovered["path"] == "primary"
    return "hypothesis-held"
assert experiment(True, "local-fixture") == "hypothesis-held"
try:
    experiment(False, "production")
except PermissionError:
    pass
else:
    raise AssertionError("unsafe experiment allowed")
```

This harmless local injected-branch experiment does not kill processes, alter networks, or test an actual backup. Real experiments require explicit operational authorization and enforced abort/cleanup controls.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not run unsanctioned production faults, start with large blast radius, or test without a recovery owner. Random failures without a hypothesis are not disciplined evidence.

## 6. How do I know I understand it?

**Blank-page check:** Write hypothesis, steady-state metric, fault, scope, abort threshold, cleanup, and evidence limits.

| Constraint change | Predict the failure and response |
| --- | --- |
| User-impact abort threshold is exceeded | Stop injection immediately and execute verified recovery; do not continue for completeness. |
| Local fallback test passes | It does not prove regional failover, real credentials, or live spare capacity. |
