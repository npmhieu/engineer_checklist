# Service Level Agreements (SLA)

[Lesson index](../../README.md) · [Previous](2.service_level_objectives.md) · [Next](4.error_budget.md)

## 1. What is it?

An SLA is an explicit service commitment with defined measurement and consequences, like a contractual delivery promise rather than an internal team target.

## 2. Why do we need it?

Customers and providers can disagree about outages, exclusions, reporting periods, and remedies when commitments are informal.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

An SLA specifies service scope, indicator, period, exclusions, evidence, and contractual consequences. Internal SLOs often leave a safety margin before the SLA threshold. Actual legal meaning depends on the agreement; an operational calculator cannot interpret terms or determine entitlement by itself.

Reference: [Primary documentation](https://sre.google/sre-book/service-level-objectives/).

### 3b. Boundaries and lifecycle

Agree terms → measure according to those terms → preserve evidence → investigate incidents and eligible claims → apply the agreed process.

## 4. How to apply / implement / use it?

Save as `service_level_agreements_demo.py`; run `python3 service_level_agreements_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
def illustrative_band(measured_availability, evidence_complete):
    if not evidence_complete:
        raise ValueError("measurement review required")
    if not 0 <= measured_availability <= 1:
        raise ValueError("invalid availability")
    return "review-remedy" if measured_availability < 0.99 else "within-demo-threshold"
assert illustrative_band(0.999, True) == "within-demo-threshold"
assert illustrative_band(0.98, True) == "review-remedy"
try:
    illustrative_band(0.999, False)
except ValueError:
    pass
else:
    raise AssertionError("unsupported conclusion issued")
```

This toy threshold is not an SLA, legal advice, a real credit schedule, or an entitlement calculation. Use the actual agreement and appropriate reviewers for exclusions, measurement, and remedies.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not publish internal SLO dashboards as contractual commitments without approval or assume every error qualifies for a remedy.

## 6. How do I know I understand it?

**Blank-page check:** Distinguish SLI, SLO, and SLA and identify which facts must be established before assessing an agreement.

| Constraint change | Predict the failure and response |
| --- | --- |
| Internal SLO is breached but SLA is not | Reliability work may still be required; the two thresholds serve different purposes. |
| Contract excludes a specific maintenance period | Apply the actual agreed measurement process rather than an invented blanket exclusion. |
