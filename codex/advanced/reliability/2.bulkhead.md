# Bulkhead

[Lesson index](../../README.md) · [Previous](1.circuit_breaker.md) · [Next](3.graceful_degradation.md)

## 1. What is it?

A bulkhead reserves separate resource capacity for failure domains, like watertight ship compartments keeping one leak from sinking everything.

## 2. Why do we need it?

A slow report provider can consume every shared thread or connection and block unrelated checkout work.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Separate bounded pools, semaphores, queues, or processes by workload/tenant/dependency. Admission should fail or defer within budget. Reserved capacity costs utilization and memory; shared lower-level dependencies can still couple supposedly isolated pools.

Reference: [Primary documentation](https://learn.microsoft.com/en-us/azure/architecture/patterns/bulkhead).

### 3b. Boundaries and lifecycle

Classify workload → acquire its bounded slot → execute with deadline → release in finally → reject/degrade only that compartment when saturated.

## 4. How to apply / implement / use it?

Save as `bulkhead_demo.py`; run `python3 bulkhead_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
from threading import BoundedSemaphore
reports = BoundedSemaphore(1)
checkout = BoundedSemaphore(1)
assert reports.acquire(blocking=False)
try:
    assert not reports.acquire(blocking=False)
    assert checkout.acquire(blocking=False)
    checkout.release()
finally:
    reports.release()
assert reports.acquire(blocking=False)
reports.release()
```

This uses real local capacity primitives to demonstrate isolation and release. It does not create thread pools, isolate memory crashes, or protect a shared database underneath both workloads.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not create unlimited pools per tenant or leave queues unbounded behind a semaphore. Excessive isolation wastes idle capacity; too little permits cascading failure.

## 6. How do I know I understand it?

**Blank-page check:** Draw resource compartments and identify a shared dependency that could still defeat them.

| Constraint change | Predict the failure and response |
| --- | --- |
| Reports saturate their slots | Checkout can retain its reserved capacity, but only if lower dependencies also have headroom. |
| Thousands of tenant-specific pools are created | Pool overhead becomes a bottleneck; use bounded classes or fair scheduling. |
