# Backup / Restore

[Lesson index](../../README.md) · [Previous](7.disaster_recovery.md) · [Next](9.recovery_point_objective.md)

## 1. What is it?

Backup/restore preserves recoverable data copies and proves they can reconstruct a valid service state, like keeping protected ledger copies and practicing reconstruction.

## 2. Why do we need it?

Replication propagates mistakes, and a successful backup command does not prove completeness, decryptability, or application correctness.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Use database-supported consistent snapshots or base backups plus required logs. Verify checksums, retention, encryption/key recovery, access separation, and restore compatibility. Restoring bytes and structural integrity is necessary but business reconciliation is also required.

Reference: [Primary documentation](https://docs.python.org/3/library/sqlite3.html#sqlite3.Connection.backup).

### 3b. Boundaries and lifecycle

Create consistent copy → protect/catalog → restore in isolation → check engine integrity and domain facts → measure recovery → retain evidence.

## 4. How to apply / implement / use it?

Save as `backup_restore_demo.py`; run `python3 backup_restore_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
import sqlite3
source = sqlite3.connect(":memory:")
backup = sqlite3.connect(":memory:")
restored = sqlite3.connect(":memory:")
source.execute("CREATE TABLE orders(id PRIMARY KEY, cents INTEGER)")
with source:
    source.execute("INSERT INTO orders VALUES(1,500)")
source.backup(backup)
with source:
    source.execute("DELETE FROM orders")
backup.backup(restored)
assert restored.execute("PRAGMA integrity_check").fetchone()[0] == "ok"
assert restored.execute("SELECT cents FROM orders WHERE id=1").fetchone()[0] == 500
with restored:
    restored.execute("UPDATE orders SET cents=999 WHERE id=1")
assert restored.execute("PRAGMA integrity_check").fetchone()[0] == "ok"
assert restored.execute("SELECT cents FROM orders WHERE id=1").fetchone()[0] != 500
for database in (source, backup, restored):
    database.close()
```

This is a real SQLite online-backup/restore exercise using separate in-memory databases. It shows structural integrity does not prove correct business values, but it does not create offsite durable backups, encrypt them, or simulate host loss.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not copy a live database's files naively or test restore over production. Do not call a replica a backup against logical deletion.
