# Event Ordering

[Lesson index](../../README.md) · [Previous](6.event_schema_versioning.md) · [Next](8.event_replay.md)

## 1. What is it?

Event ordering preserves a chosen business sequence of facts, like processing an account's numbered statements in order rather than sorting envelopes by arrival time.

## 2. Why do we need it?

An older update arriving late can overwrite newer state, and wall-clock timestamps can disagree across producers.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Choose an ordering scope, usually aggregate or partition. Assign a sequence under the authoritative write transaction; consumers detect duplicates and gaps. Buffering gaps costs memory and can stall progress; concurrent independent aggregates need not share one global order.

Reference: [Primary documentation](https://kafka.apache.org/43/implementation/distribution/).

### 3b. Boundaries and lifecycle

Owner commits sequence → publish with stable key → consumer checks expected version → apply/checkpoint or pause/reconcile missing facts.

## 4. How to apply / implement / use it?

Save as `event_ordering_demo.py`; run `python3 event_ordering_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
state = {"version": 0, "name": ""}
def apply(event):
    if event["version"] <= state["version"]:
        return "duplicate-or-old"
    if event["version"] != state["version"] + 1:
        raise ValueError("sequence gap")
    state.update(version=event["version"], name=event["name"])
    return "applied"
assert apply({"version": 1, "name": "first"}) == "applied"
try:
    apply({"version": 3, "name": "third"})
except ValueError:
    pass
else:
    raise AssertionError("gap ignored")
assert state["version"] == 1
assert apply({"version": 1, "name": "first"}) == "duplicate-or-old"
```

This single-aggregate model assumes every version corresponds to an event this consumer should see. Filtered streams may intentionally skip aggregate versions and need a different sequence contract. Durable atomic effect/checkpoint storage is omitted.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not impose global order without a global invariant. Do not treat event time, broker offset, and aggregate version as interchangeable.

## 6. How do I know I understand it?

**Blank-page check:** Explain arrival order, occurrence time, causal dependencies, and per-aggregate sequence with two concurrent producers.

| Constraint change | Predict the failure and response |
| --- | --- |
| An expected fact is missing forever | Bound buffering and reconcile or quarantine; do not wait silently without an owner. |
| Several aggregates share a partition | Partition ordering does not create a cross-aggregate business transaction. |
