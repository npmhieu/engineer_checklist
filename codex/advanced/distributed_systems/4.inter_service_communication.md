# Inter-service Communication

[Lesson index](../../README.md) · [Previous](3.microservices_architecture.md) · [Next](5.event_driven_architecture_at_scale.md)

## 1. What is it?

Inter-service communication carries requests or facts across service boundaries, like choosing a phone call for an immediate answer or a registered letter for later action.

## 2. Why do we need it?

Unbounded synchronous chains accumulate latency and failures; fire-and-forget messages can lose important work or hide authorization gaps.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Synchronous RPC couples the caller's waiting budget to the receiver. Durable messaging separates acceptance from completion. Both require workload identity, action/resource authorization, schema validation, stable operation IDs, bounded payloads, and trace context; internal placement is not trust.

Reference: [Primary documentation](https://cheatsheetseries.owasp.org/cheatsheets/Microservices_Security_Cheat_Sheet.html).

### 3b. Boundaries and lifecycle

Establish identity and remaining budget → call or persist message intent → validate at receiver → commit locally → return or acknowledge under declared semantics.

## 4. How to apply / implement / use it?

Save as `inter_service_communication_demo.py`; run `python3 inter_service_communication_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
def receive(principal, request):
    if principal != "checkout-service":
        raise PermissionError("caller not allowed")
    if request["remaining_ms"] <= 0:
        raise TimeoutError("budget exhausted")
    return {"accepted": request["operation_id"]}
assert receive("checkout-service", {"operation_id": "op-1", "remaining_ms": 100}) == {"accepted": "op-1"}
for principal, budget, expected in [
    ("unknown", 100, PermissionError),
    ("checkout-service", 0, TimeoutError),
]:
    try:
        receive(principal, {"operation_id": "op-2", "remaining_ms": budget})
    except expected:
        pass
    else:
        raise AssertionError("boundary policy bypassed")
```

Principal and budget are controlled fixtures, not trusted headers or a secure transport. Production derives identity from verified credentials and defines delegation, endpoint authorization, retry safety, and network timeouts.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not accept caller identity from arbitrary headers, retry non-idempotent effects blindly, or send a whole ORM entity as a contract.

## 6. How do I know I understand it?

**Blank-page check:** Choose synchronous or asynchronous communication for three workflows and explain acceptance versus completion.

| Constraint change | Predict the failure and response |
| --- | --- |
| A service forwards a user's request | Authorize both service capability and delegated user/resource scope. |
| A downstream call times out | Preserve operation identity and reconcile possible completion before retrying. |
