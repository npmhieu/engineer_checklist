# Environment / Configuration

[Lesson index](../../README.md) · Previous: [Git](1.git.md) · Next: [Logging](3.logging.md)

## 1. What is it?

Configuration supplies deployment-specific values to the same application behavior, like setting a machine's destination and operating limits without rebuilding its motor.

Environment variables are one configuration source, not a complete secret-management system or a reason to skip validation.

## 2. Why do we need it?

Hard-coded production credentials leak through source and make local tests contact real systems. String values such as `"false"` can become truthy when parsed carelessly.

Specific pain: a service starts with an empty database URL or debug mode enabled in production and fails only after accepting traffic.

## 3. Under the hood / mechanism / system flow

### 3a. Sources, parsing, and snapshots

Process environment values are strings inherited at startup. Applications may also read files, command-line arguments, or a secret/configuration service; precedence must be explicit. Parse into typed values once, validate combinations, and inject a stable configuration object.

Reading local values is cheap; remote secret retrieval adds authentication, network dependency, caching, and rotation behavior. Environment variables can appear in process/container diagnostics and should not be logged wholesale. [Twelve-Factor configuration guidance](https://12factor.net/config) explains separating deploy-specific config from code; secret protection remains an additional responsibility.

### 3b. Startup and change lifecycle

```text
Resolve sources/precedence → parse → validate required values/invariants
    → construct dependencies → declare ready
```

Fail before serving when required configuration is invalid. Hot reload needs its own atomicity/freshness policy; reading changing configuration independently on every request can mix incompatible values. A release should identify both artifact and configuration version without disclosing secrets.

## 4. How to apply / implement / use it?

Save as `configuration_demo.py`; run `python3 configuration_demo.py`. A mapping stands in for `os.environ` so the example does not mutate your environment or connect anywhere.

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Config:
    mode: str
    debug: bool
    database_url: str
    pool_size: int

def load_config(values):
    mode = values.get("APP_ENV", "development")
    debug = values.get("APP_DEBUG", "false")
    database_url = values.get("APP_DATABASE_URL", "")
    pool = values.get("APP_POOL_SIZE", "5")
    if mode not in {"development", "production"} or debug not in {"true", "false"}:
        raise ValueError("INVALID_MODE_OR_DEBUG")
    if not isinstance(database_url, str) or not database_url.strip():
        raise ValueError("DATABASE_URL_REQUIRED")
    if not isinstance(pool, str) or not pool.isascii() or not pool.isdecimal() or not 1 <= int(pool) <= 100:
        raise ValueError("INVALID_POOL_SIZE")
    if mode == "production" and debug == "true":
        raise ValueError("DEBUG_FORBIDDEN_IN_PRODUCTION")
    return Config(mode, debug == "true", database_url, int(pool))

base = {"APP_DATABASE_URL": "sqlite:///local.sqlite", "APP_DEBUG": "false"}
assert load_config(base).debug is False
for values in [{}, {**base, "APP_POOL_SIZE": "0"}, {**base, "APP_DEBUG": "yes"}, {**base, "APP_ENV": "production", "APP_DEBUG": "true"}]:
    try:
        load_config(values)
    except ValueError:
        pass
    else:
        raise AssertionError("Unsafe configuration accepted")
print("happy: immutable typed configuration; unhappy: missing/invalid/unsafe values fail at startup")
```

The URL is a placeholder, not a complete driver/URL validator. Production validation must match supported backends and trust rules. Never print the whole config object when it contains credentials; even generated dataclass representations can disclose them.

## 5. When should I NOT use this? Trade-offs and anti-patterns

- Stable domain constants do not all need deployment knobs.
- Do not silently default missing production secrets to development credentials.
- Do not use `bool(environment_value)` for textual booleans.
- Do not bake secrets into container images or dump environment/configuration into error logs.

Too many options multiply supported combinations. Keep defaults safe, document units, and validate interdependent settings rather than creating endless flags.

## 6. How do I know I understand it?

**Blank-page check:** list configuration sources, precedence, types, units, required values, secret fields, and the exact point startup becomes ready.

| Constraint change | Predict the failure and response |
| --- | --- |
| `APP_DEBUG=false` is supplied | Parse explicitly; nonempty text is not a true boolean |
| Secret service is unavailable | Follow an explicit secure startup/cache policy, not a silent insecure fallback |
| A value hot-reloads | Update a coherent version atomically and define in-flight behavior |
| Pool size increases on every replica | Total database connection demand multiplies |

You understand configuration when one artifact can run safely in different deployments without hidden defaults or secret disclosure.
