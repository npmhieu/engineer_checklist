# Export / Import

[Lesson index](../../README.md) · Previous: [Notifications](3.notifications.md) · Next: [Audit Log](5.audit_log.md)

## 1. What is it?

Export converts application data into a portable contract and import validates that contract before applying changes, like sending and receiving a carefully labeled spreadsheet rather than copying arbitrary database internals.

## 2. Why do we need it?

Users need bulk entry, migration, and offline analysis. Without a defined format, a renamed column, locale-dependent number, duplicate row, or partial failure can silently corrupt data.

Specific pain: the first 99 imported rows persist before row 100 fails, leaving the user unsure which rows to retry.

## 3. Under the hood / mechanism / system flow

### 3a. Parsing, batching, and memory

Use a real CSV parser for quotes/newlines; splitting on commas is incorrect. Specify encoding, headers, field types, units, and duplicate policy. [Python's CSV module](https://docs.python.org/3/library/csv.html) implements the file grammar, not domain validation.

Buffering all rows enables whole-file validation but uses proportional memory. Streaming/batching bounds memory while introducing partial-progress, checkpoint, and retry semantics. Exact large exports may need a consistent snapshot rather than live pagination.

### 3b. Data and security boundary

```text
Import: authorize → bound bytes/rows → parse → validate → stage/apply → report outcome
Export: authorize/filter → stable projection → encode safely → protected download
```

Spreadsheet cells beginning with formula markers can execute as formulas in some viewers; CSV quoting alone does not neutralize that behavior. A conservative text-field policy can reject dangerous-leading values, at a usability cost. Define spreadsheet-safe presentation separately from machine interchange; do not silently mutate source records. See [OWASP's CSV injection explanation](https://community.owasp.org/attacks/CSV_Injection).

## 4. How to apply / implement / use it?

Save as `export_import_demo.py`; run `python3 export_import_demo.py`. This bounded UTF-8 CSV import is all-or-nothing, with exact `title,quantity` headers and no upsert behavior.

```python
import csv
import io
import re
import sqlite3

database = sqlite3.connect(":memory:")
database.execute("CREATE TABLE items (title TEXT NOT NULL UNIQUE, quantity INTEGER NOT NULL CHECK (quantity > 0))")

def import_csv(raw):
    if len(raw) > 16384:
        raise ValueError("FILE_TOO_LARGE")
    reader = csv.DictReader(io.StringIO(raw.decode("utf-8"), newline=""))
    if reader.fieldnames != ["title", "quantity"]:
        raise ValueError("INVALID_HEADERS")
    rows = []
    for row in reader:
        title, quantity = row.get("title"), row.get("quantity")
        if set(row) != {"title", "quantity"} or not isinstance(title, str) or not 1 <= len(title) <= 120:
            raise ValueError("INVALID_ROW")
        if not isinstance(quantity, str) or re.fullmatch(r"[1-9][0-9]{0,5}", quantity) is None:
            raise ValueError("INVALID_QUANTITY")
        rows.append((title, int(quantity)))
        if len(rows) > 100:
            raise ValueError("TOO_MANY_ROWS")
    with database:
        database.executemany("INSERT INTO items VALUES (?, ?)", rows)

def export_csv():
    output = io.StringIO(newline="")
    writer = csv.writer(output)
    writer.writerow(["title", "quantity"])
    for title, quantity in database.execute("SELECT title, quantity FROM items ORDER BY title"):
        if title.lstrip().startswith(("=", "+", "-", "@")) or title.startswith(("\t", "\r", "\n")):
            raise ValueError("UNSAFE_SPREADSHEET_TEXT")
        writer.writerow([title, quantity])
    return output.getvalue()

import_csv(b'title,quantity\n"Book, blue",2\nPen,3\n')
assert '"Book, blue",2' in export_csv()
for raw in [b"title,quantity\nNew,4\nBad,no\n", b"title,quantity\nNew,4\nPen,1\n"]:
    try:
        import_csv(raw)
    except (ValueError, sqlite3.IntegrityError):
        pass
    else:
        raise AssertionError("Invalid batch succeeded")
assert database.execute("SELECT COUNT(*) FROM items").fetchone()[0] == 2
database.close()
print("happy: quoted CSV roundtrip; unhappy: invalid/duplicate batch leaves no partial insert")
```

The spreadsheet check is deliberately restrictive for this text field, not a universal guarantee for every application/viewer. A real HTTP adapter must protect downloads, enforce tenant scope, bound parsing, and map row errors safely. Bulk replacement/deletion is not implemented.

## 5. When should I NOT use this? Trade-offs and anti-patterns

- Do not expose raw tables/password hashes as a convenient export format.
- Do not run huge exports in an interactive request or hold a write lock while generating a download.
- Do not silently skip invalid rows without a documented partial-success report.
- Do not interpret retrying a file as harmless without duplicate/idempotency rules.

Large jobs often need background execution, staged validation, progress, quotas, and protected result expiry. These are additional contracts, not merely a larger upload limit.

## 6. How do I know I understand it?

**Blank-page check:** specify grammar, encoding, types, authorization, atomicity, duplicate policy, and a retry outcome for one import format.

| Constraint change | Predict the failure and response |
| --- | --- |
| File grows to millions of rows | Stage/stream/batch with explicit progress and partial-failure semantics |
| A title starts with `=` | Treat spreadsheet presentation as an injection boundary |
| Input is retried | Decide reject/upsert/deduplicate rather than accidentally duplicating records |
| Data changes during export | Define live versus point-in-time consistency |

You understand export/import when users can predict exactly what changed, what failed, and what retrying will do.
