# Smoke Test

[Lesson index](../../README.md) · [Previous](5.regression_test.md) · [Next](7.load_test.md)

## 1. What is it?

A smoke test is a small critical-path check that a candidate is usable enough for further evaluation, like starting a serviced engine before a long road test.

## 2. Why do we need it?

A successful build or process start does not prove configuration, essential schema, and minimum application wiring are usable.

## 3. Under the hood / mechanism / system flow

### 3a. Implementation, state, and cost

Keep the suite short, safe, and representative of required wiring. Readiness and a disposable business probe answer different questions; one static 200 response can conceal broken dependencies. Run against the actual candidate when claiming deployment confidence, and capture version/config context with failures.

Reference: [Primary documentation](https://sre.google/workbook/canarying-releases/).

### 3b. Boundaries and lifecycle

Build/deploy candidate → confirm startup and required wiring → perform bounded safe probe → block promotion or proceed to deeper tests → retain diagnostics and clean up.

## 4. How to apply / implement / use it?

Save as `smoke_test_demo.py`; run `python3 smoke_test_demo.py`. Standard library only. Assertions cover successful behavior and a rejected, failed, or unsafe case.

```python
import sqlite3
def readiness(database):
    try:
        database.execute("SELECT id FROM tasks LIMIT 1").fetchall()
    except sqlite3.OperationalError:
        return 503
    return 200
def promotion_gate(database):
    if readiness(database) != 200:
        raise RuntimeError("candidate smoke check failed")
    return "proceed"
healthy = sqlite3.connect(":memory:")
broken = sqlite3.connect(":memory:")
try:
    healthy.execute("CREATE TABLE tasks(id INTEGER PRIMARY KEY)")
    assert promotion_gate(healthy) == "proceed"
    try:
        promotion_gate(broken)
    except RuntimeError:
        pass
    else:
        raise AssertionError("missing schema passed the gate")
finally:
    healthy.close()
    broken.close()
```

Expected: the schema-backed probe passes and the missing-table probe blocks promotion. This is a real local dependency/gate check, not a deployed endpoint or complete smoke suite. It proves neither write permissions nor all migrations/business operations; add a safe isolated critical workflow when those are required.

## 5. When should I NOT use this? Trade-offs and anti-patterns

Do not relabel a long regression suite as smoke or send real payments/notifications from a routine deployment probe. A passing smoke test is not comprehensive acceptance.

## 6. How do I know I understand it?

**Blank-page check:** Choose the smallest checks that reject a badly wired release and list the important risks they still leave untested.

| Constraint change | Predict the failure and response |
| --- | --- |
| Probe always returns 200 without touching dependencies | It verifies routing only, not this schema requirement. |
| Database is temporarily slow | Use bounded probe deadlines and readiness policy; do not trigger a restart storm through dependency-heavy liveness checks. |
